# 0028 locllmw 概览：硬件检测与智能推荐

- 状态：已落地
- 日期：2026-11-14
- 相关文档：[ADR 0015](0015-llm-serve-tuning.md)、[ADR 0025](0025-sidebar-page-navigation.md)、[ADR 0027](0027-locllmw-rename.md)

## 背景

`locllmw` 的「概览」原先只有运行中服务与一组快捷按钮，用户仍需自己判断
本机能不能跑某个模型、该用什么档位、大概能到多少 tokens/s。硬件信息只零散
出现在「监测」页且是运行时采样，模型盘也无法在窗口里直接改。

目标：概览页第一眼给出「这台机器 + 模型盘」的完整硬件画像，并基于该画像
推荐模型与启动配置；没有实测数据时明确标注「预测」，跑过性能测试后同一
模型自动改用「实测」值。

## 决策

### 1. 硬件快照持久化

- 页面自上而下：**硬件与模型盘 → 智能推荐 → 已加载模型**；移除原快捷入口。
- 快照字段：CPU（型号 / 核 / 线程）、内存、NVIDIA GPU 型号与显存、固定磁盘
  列表、主模型目录、检测时间；结构带 `schema: 1`。
- 首次打开且配置中没有快照时，后台检测并写入 `~/.fcmd/ui/locllmw.json`；
  之后直接展示缓存，提供「重新检测」按钮。检测在后台线程执行，失败只更新
  状态文案，不阻塞窗口。
- 检测来源：`psutil`（CPU / 内存 / 磁盘）、Windows 注册表或 `/proc/cpuinfo`
  （CPU 型号）、`llmengine.detect_gpu`（`nvidia-smi`）。测试注入 `runner`，
  不依赖真实 GPU。

### 2. 模型盘

- 展示选中模型所在盘；未选模型时用主模型目录。分区按**最长挂载点前缀**匹配。
- 「修改模型盘…」选择目录后写入 `llmenv` 的 `models_roots`（替换当前列表），
  刷新硬件面板并重新扫描模型；不新增 `locllmw` 私有配置，保持与 CLI 同源。

### 3. 智能推荐与性能口径

- 纯逻辑在 `_locllmw_recommend.py`：按模型大小从大到小，选择能整卡放下的
  模型（显存不足时自动降 KV 或收缩上下文；仍放不下则跳过），档位优先取模型
  能力标签（代码 / 推理 / 对话等），启动参数用 `_llmtune.resolve("auto", ...)`。
- 性能预测以 ADR 0015 的参考机器（RTX 5090 D 32GB + Qwen3-Coder-30B-A3B
  Q5_K_M，单请求解码 250 tok/s、8K 预填充 16.2k tok/s）为基准，按模型大小
  与显存比例外推，并叠加调优策略折减；无 GPU 时按 CPU 大幅折减。
- 实测来源：性能测试的 `short` / `generate` 场景写入解码速度，`concurrent4`
  写聚合吞吐；记录按模型路径（`llmenv.path_key`）保存在配置文件，推荐优先
  使用实测解码值。预填充目前没有采样，始终标注「预测」。
- 性能文本逐项标注来源，例如「解码 250 tok/s（实测）· 预填充 16.2k tok/s（预测）」，
  不把整行笼统标成实测。

### 4. 刷新时机

硬件检测完成、模型扫描完成、切换选中模型、修改模型盘、性能测试结果落表后
刷新硬件面板与推荐表；推荐表最多 3 行，避免概览页被撑长。

## 验证

- `tests/apps/locllm/test_locllmw_overview.py`：快照序列化 / 非法输入、最长
  挂载点匹配、磁盘格式化、注入 runner 的硬件检测、性能预测单调性、
  推荐筛选 / 实测覆盖 / CPU-only / limit。
- `tests/apps/locllm/test_cli_llmserve.py`：配置读写覆盖 hardware / measured。
- 真实 Tk 冒烟：10 页导航、硬件检测完成、模型扫描后推荐表出现 3 行。

## 交接

- 预测公式是经验外推，不是逐卡基准表；接入更多实测或按 GPU 型号维护基准表
  后，应替换 `predict_performance` 的系数。
- 预填充实测需要性能测试增加 prompt 吞吐采样；在此之前推荐行的预填充保持
  「预测」标注。
- 多模型目录时概览只显示主目录所在盘；完整目录列表仍在「设置」页与
  `fcmd llmenv show`。
