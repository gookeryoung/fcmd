# 0028 locllmw 概览：硬件检测与智能推荐

- 状态：已落地
- 日期：2026-11-14
- 相关文档：[ADR 0015](0015-llm-serve-tuning.md)、[ADR 0025](0025-sidebar-page-navigation.md)、[ADR 0027](0027-locllmw-rename.md)

## 背景

`locllmw` 的「概览」原先只有运行中服务与一组快捷按钮，用户仍需自己判断
本机能不能跑某个模型、该用什么档位、大概能到多少 tokens/s。硬件信息只零散
出现「监测」页且是运行时采样。

目标：概览页第一眼给出本机的完整硬件画像，并基于该画像
推荐模型与启动配置；没有实测数据时明确标注「预测」，跑过性能测试后同一
模型自动改用「实测」值。

## 决策

### 1. 硬件快照持久化

- 页面自上而下：**环境健康状态条 → 硬件信息 → 智能推荐**；原快捷入口与
  「已加载模型」面板已移除（运行中服务的操作在运行页 / 监测页完成）。
- 快照字段：CPU（型号 / 核 / 线程）、内存、NVIDIA GPU 型号与显存、固定磁盘
  列表、检测时间；结构带 `schema: 1`（快照仍保留 `model_root` 字段供缓存与
  其他页面读取，概览不再展示）。
- 首次打开且配置中没有快照时，后台检测并写入 `~/.fcmd/ui/locllmw.json`；
  之后直接展示缓存，标题旁提供「重新检测」文字链接。检测在后台线程执行，失败只更新
  状态文案，不阻塞窗口。
- 检测来源：`psutil`（CPU / 内存 / 磁盘）、Windows 注册表或 `/proc/cpuinfo`
  （CPU 型号）、`llmengine.detect_gpu`（`nvidia-smi`）。测试注入 `runner`，
  不依赖真实 GPU。

### 2. 模型盘

- 页面只展示显卡 / 处理器 / 内存 / 模型盘四行，不再列出全部硬盘。
- 硬件行右侧各有一个**环形占用表**：环心百分比、环下简报已用 / 总量，
  数据来自现有系统采样循环（每 1s），停止监控或采样不可用时归零并标注
  「未监控 / 暂不可用」。
- 展示选中模型所在盘；未选模型时用主模型目录。分区按**最长挂载点前缀**匹配。
- 模型目录在概览只做只读摘要，行内「修改」文字链接跳转设置 → 存储；写入
  入口只有一处，不新增 `locllmw` 私有配置，保持与 CLI 同源。

### 3. 智能推荐与性能口径

- 纯逻辑在 `_locllmw_recommend.py`：按模型大小从大到小，选择能整卡放下的
  模型（显存不足时自动降 KV 或收缩上下文；仍放不下则跳过），档位优先取模型
  能力标签（代码 / 推理 / 对话等），启动参数用 `_llmtune.resolve("auto", ...)`。
- 性能预测以 ADR 0015 的参考机器（RTX 5090 D 32GB + Qwen3-Coder-30B-A3B
  Q5_K_M，单请求解码 250 tok/s、8K 预填充 16.2k tok/s）为基准，按模型大小
  与显存比例外推，并叠加调优策略折减；无 GPU 时按 CPU 大幅折减。
- 实测来源：性能测试的 `short` / `generate` 场景写入解码速度，`concurrent4`
  写聚合吞吐；记录按模型路径（`llmenv.path_key`）保存在配置文件，推荐优先
  使用实测解码值。预填充目前没有采样，始终标注「预测」。
- 性能文本逐项标注来源，例如「解码 250 tok/s（实测）· 预填充 16.2k tok/s（预测）」，
  不把整行笼统标成实测。
- 展示采用**自定义列表行**而非表格：模型名一行大字加粗；下方参数与性能用小字，
  关键数值（档位 / 上下文 / KV / batch / 并行 / 解码 / 预填充 / 来源）加粗；
  依据文案放在行 tooltip，避免长文本占版面。

### 4. 刷新时机

硬件检测完成、模型扫描完成、切换选中模型、性能测试结果落表后刷新硬件面板
与推荐列表；显存 / 内存占用表由系统监控采样实时刷新。推荐列表最多 3 行，
避免概览页被撑长。

### 5. 环境健康状态条

- 概览与运行页顶部各有一条状态条，数据来自现有的模型扫描线程：引擎是否已安装、
  模型目录是否存在 / 可读 / 含 GGUF、`nvidia-smi` 是否能检测到 GPU、默认端口
  是否被占用。
- 无异常时显示「环境检查通过」并禁用右侧按钮；有异常时汇总为一行「注意：…」，
  按钮按优先级改为「去设置 / 去模型页 / 去运行页」并跳转对应分页。
- 扫描线程只回传不可变结果对象；Tk 变量一律在主线程读取后再传给后台线程，
  避免后台线程访问 Tk 导致 `main thread is not in main loop`。
- 扫描结果为空但目录可读时归类为「模型目录中未找到 GGUF 文件」，与目录不存在、
  无权限、解析失败区分；原因同时写入监测页日志。

### 6. 可执行入口

- 「智能推荐」选中一行可「用此配置启动」：把模型、档位、上下文、调优策略写入
  运行页表单，KV 以推荐值为准，然后切到运行页并滚动到启动参数区；不直接启动，
  仍需用户确认计划或点启动。

## 验证

- `tests/apps/locllm/test_locllmw_overview.py`：快照序列化 / 非法输入、最长
  挂载点匹配、磁盘格式化、注入 runner 的硬件检测、性能预测单调性、
  推荐筛选 / 实测覆盖 / CPU-only / limit。
- `tests/apps/locllm/test_cli_llmserve.py`：配置读写覆盖 hardware / measured。
- `tests/apps/locllm/test_locllmw_ui.py`：模型目录扫描的错误分类（不存在 /
  无权限 / 其它 `OSError` / 空目录 / 正常）、推荐配置带入运行页的参数覆盖顺序。
- 离屏 Qt 冒烟：七页导航、硬件检测完成、模型扫描后推荐列表出现 3 行；健康状态条
  在正常环境显示「环境检查通过」，注入异常后按钮可跳转到对应分页。

## 交接

- 预测公式是经验外推，不是逐卡基准表；接入更多实测或按 GPU 型号维护基准表
  后，应替换 `predict_performance` 的系数。
- 预填充实测需要性能测试增加 prompt 吞吐采样；在此之前推荐行的预填充保持
  「预测」标注。
- 模型目录的查看 / 修改统一在「设置」页与 `fcmd llmenv show`，概览不再重复。
