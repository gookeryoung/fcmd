# 0028 locllmw 概览：硬件检测与智能推荐

- 状态：已落地
- 日期：2026-11-14
- 相关文档：[ADR 0015](0015-llm-serve-tuning.md)、[ADR 0025](0025-sidebar-page-navigation.md)、[ADR 0027](0027-locllmw-rename.md)

## 背景

`locllmw` 的「概览」原先只有运行中服务与一组快捷按钮，用户仍需自己判断
本机能不能跑某个模型、该用什么档位、大概能到多少 tokens/s。硬件信息只零散
原先只在运行时临时采样。

目标：概览页第一眼给出本机的完整硬件画像，并基于该画像
推荐模型与启动配置；没有实测数据时明确标注「预测」，跑过性能测试后同一
模型自动改用「实测」值。

## 决策

### 1. 硬件快照持久化

- 页面自上而下：**环境健康状态条 → 系统信息 → 智能推荐**；原快捷入口与
  「已加载模型」面板已移除（运行中服务的操作在运行页完成）。
- 快照字段：CPU（型号 / 核 / 线程）、内存、NVIDIA GPU 型号与显存、固定磁盘
  列表、检测时间；结构带 `schema: 1`（快照仍保留 `model_root` 字段供缓存与
  其他页面读取，概览不再展示）。
- 首次打开且配置中没有快照时，后台检测并写入 `~/.fcmd/ui/locllmw.json`；
  之后直接展示缓存，标题旁提供「重新检测」文字链接。检测在后台线程执行，失败只更新
  状态文案，不阻塞窗口。
- 检测来源：`psutil`（CPU / 内存 / 磁盘）、Windows 注册表或 `/proc/cpuinfo`
  （CPU 型号）、`llmengine.detect_gpu`（`nvidia-smi`）。测试注入 `runner`，
  不依赖真实 GPU。

### 2. 模型盘

- 页面只展示显卡 / 处理器 / 内存几行，不再列出全部硬盘。
- 硬件规格下方是 GPU / CPU / 内存三块**实时负载**：主格图 + 占用率，
  标题后用小字提示关键信息（GPU 显存 / 功耗、CPU 频率 / 服务 CPU、
  内存已用 / 交换）；数据来自系统采样循环（每 1s），未采样时显示 `-`
  并清空格图。格图按使用率分三档配色：<60% 充足（`success` 绿）、
  60%～85% 偏紧（`warning` 琥珀）、≥85% 告急（`danger` 红），颜色取自
  当前主题。概览页不做整页滚动：页面高度不足时只由推荐列表内部滚动；
  「启动服务」按钮固定在推荐列表卡片之外。
- 系统信息右侧展示实时性能：生成 tok/s 大字 + 提示速率 / 请求队列 / KV /
  累计 tokens 小字，数据来自概览页每秒采样；
  未运行 / 采样失败时显示 `-` 与对应胶囊标签。
- 展示选中模型所在盘；未选模型时用主模型目录。分区按**最长挂载点前缀**匹配。
- 模型目录在概览只做只读摘要，行内「修改」文字链接跳转设置 → 存储；写入
  入口只有一处，不新增 `locllmw` 私有配置，保持与 CLI 同源。

### 3. 智能推荐与性能口径

- 纯逻辑在 `_locllmw_recommend.py`：按模型大小从大到小筛选能整卡放下的模型
  （显存不足时自动降 KV 或收缩上下文；仍放不下则跳过），凑满 3 条后按评分
  从高到低展示；评分相同时按模型大小从大到小、再按路径排序。档位优先取模型
  能力标签（代码 / 推理 / 对话等），启动参数用 `_llmtune.resolve("auto", ...)`。
- 性能预测以 ADR 0015 的参考机器（RTX 5090 D 32GB + Qwen3-Coder-30B-A3B
  Q5_K_M，单请求解码 250 tok/s、8K 预填充 16.2k tok/s）为基准，按模型大小
  与显存比例外推，并叠加调优策略折减；无 GPU 时按 CPU 大幅折减。
- 实测来源：性能测试的 `short` / `generate` 场景写入解码速度，`concurrent4`
  写聚合吞吐；记录按模型路径（`llmenv.path_key`）保存在配置文件，推荐优先
  使用实测解码值。预填充目前没有采样，始终按预测处理。
- 性能来源用行内胶囊标签标注：`实测`（解码来自性能测试）或 `预测`（按参考
  机器外推）；标签 tooltip 说明预填充仍为预测，不把性能文本混排成来源说明。
- 展示采用**自定义列表行**而非表格：模型名一行大字加粗；下方参数与性能用小字，
  关键数值（档位 / 上下文 / KV / batch / 并行 / 解码 / 预填充 / 来源）加粗；
  依据文案放在行 tooltip，避免长文本占版面。
- 列表铺满推荐卡片的宽度与剩余高度：长模型名中间省略（tooltip 保留全名），
  行不把视口撑宽、不出现横向滚动；行高固定，行数超出可用高度时列表内部纵向滚动。
- 自定义行用 `setItemWidget` 挂在列表上，Qt 只在行变大时重排行几何，窗口反复
  拖宽再拖窄后行会残留上一次的更大宽度、右侧性能摘要被挤出视口；因此列表在
  每次尺寸变化后按当前可视区域重新对齐每行几何（`RecommendationList`）。

#### 3.1 推荐评分与配色

- 每条推荐按四个维度打分（`score_recommendation`），各项取整后相加，总分即四项之和：
  - **显存余量 40 分**：预计占用 ≤55% 显存得满分，用满 100% 得 0 分；
    CPU 推理没有显存约束，给 55% 的中性分。
  - **上下文 25 分**：实际上下文 / 档位默认上下文；被显存压缩得越狠分越低。
  - **KV 精度 15 分**：相对档位默认精度的质量系数（f16 1.0 / q8_0 0.7 / q4_0 0.4），
    降精度换显存要扣分。
  - **解码速度 20 分**：解码 tok/s / 舒适线 20 tok/s，达到或超过舒适线得满分。
- 评分只反映「这份配置在这台机器上多合适」，不代表模型能力；实测 / 预测仍由
  `basis` 与性能文本区分，不参与加分。
- 档位与配色：≥80 极佳（`success` 绿）、≥65 合适（`accent` 蓝）、≥50 可用（`warning` 琥珀）、
  其余勉强（`danger` 红）。行左侧是圆形评分框（数字 + 档位色填充）；整行按档位
  使用同一色系：边框着档位色、底色取档位色 16% 透明度（QSS 由调色板派生
  `*_soft` token）。配色全部走主题 QSS 的 `band` 属性规则，切主题自动跟随；
  选中 / 悬停只加粗边框，不覆盖档位色系。
- 评分明细（显存 / 上下文 / KV / 性能）与推荐依据一起放进行与评分框的 tooltip，
  不在行内堆叠文字。

### 4. 刷新时机

硬件检测完成、模型扫描完成、切换选中模型、性能测试结果落表后刷新硬件面板
与推荐列表；显存 / 内存占用表由系统监控采样实时刷新。推荐列表最多 3 行，
避免概览页被撑长。

### 5. 环境健康状态条

- 概览与运行页顶部各有一条状态条，数据来自现有的模型扫描线程：引擎是否已安装、
  模型目录是否存在 / 可读 / 含 GGUF、`nvidia-smi` 是否能检测到 GPU、默认端口
  是否被占用。
- 无异常时显示「环境检查通过」并禁用右侧按钮；有异常时汇总为一行「注意：…」，
  按钮按优先级改为「去设置 / 去模型页 / 去运行页」并跳转对应分页。
- 扫描线程只回传不可变结果对象；Tk 变量一律在主线程读取后再传给后台线程，
  避免后台线程访问 Tk 导致 `main thread is not in main loop`。
- 扫描结果为空但目录可读时归类为「模型目录中未找到 GGUF 文件」，与目录不存在、
  无权限、解析失败区分；原因同时写入服务日志（「帮助 → 服务日志…」）。

### 6. 可执行入口

- 「智能推荐」选中一行可点「启动服务」：按钮复用运行页 `RunPrimary` 尺寸
  （40px 高、标题字号、更大的左右内边距），把模型、档位、上下文、调优策略写入
  运行页表单，KV 以推荐值为准，然后切到运行页并滚动到启动参数区；不直接启动，
  仍需用户确认计划或点启动。推荐卡片底部不再放长段说明，空态 / 未选中提示
  统一走状态栏。

## 验证

- `tests/apps/locllm/test_locllmw_overview.py`：快照序列化 / 非法输入、最长
  挂载点匹配、磁盘格式化、注入 runner 的硬件检测、性能预测单调性、
  推荐筛选 / 候选按大小取大 / 展示按评分降序 / 实测覆盖 / CPU-only / limit。
- `tests/apps/locllm/test_cli_llmserve.py`：配置读写覆盖 hardware / measured。
- `tests/apps/locllm/test_locllmw_ui.py`：模型目录扫描的错误分类（不存在 /
  无权限 / 其它 `OSError` / 空目录 / 正常）、推荐配置带入运行页的参数覆盖顺序。
- 离屏 Qt 冒烟：六页导航、硬件检测完成、模型扫描后推荐列表出现 3 行；健康状态条
  在正常环境显示「环境检查通过」，注入异常后按钮可跳转到对应分页；注入系统采样后
  概览硬件卡的 GPU / CPU / 内存格图与显存 / 交换副条同步更新（档位配色见
  `segment_band` 单测）。

## 交接

- 预测公式是经验外推，不是逐卡基准表；接入更多实测或按 GPU 型号维护基准表
  后，应替换 `predict_performance` 的系数。
- 预填充实测需要性能测试增加 prompt 吞吐采样；在此之前推荐行的预填充保持
  「预测」标注。
- 模型目录的查看 / 修改统一在「设置」页与 `fcmd llmenv show`，概览不再重复。
