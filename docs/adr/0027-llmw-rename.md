# 0027 locllmw：llmservew 改名与侧边栏信息架构

- 状态：已落地
- 日期：2026-11-14
- 相关文档：[ADR 0015](0015-llm-serve-tuning.md)、[ADR 0025](0025-sidebar-page-navigation.md)、[ADR 0026](0026-llm-app-migration.md)

## 背景

`llmservew` 最初只做「服务启动参数 + 运行监控」两件事；随功能增长，它已经
变成本地 LLM 的统一入口：模型目录与显存适配、服务生命周期、指标与日志、
性能测试，以及后续要接的对话、代理、画图、视频、音频。原名字与三页
（启动配置 / 运行监控 / 性能测试）都不再匹配职责：

- 「serve」只覆盖运行服务，不覆盖模型选择与多模态场景；
- `llmservew` 与 CLI `llmserve` 强绑定，容易让人以为它只是服务的图形外壳；
- 页面到 10 个量级时，顶部标签条会挤压内容宽度，且新增场景无落点。

## 决策

### 1. 改名 `llmservew` → `locllmw`

- 模块：`src/fcmd/apps/llm/llmservew.py` → `llmw.py`；
- 内部拆分：`_llmservew_bench/monitor/ui.py` → `_llmw_bench/monitor/ui.py`；
- 类：`ServeWindow` / `_ServeWindowUI` / `_ServeWindowBench` / `_ServeWindowMonitor`
  / `ServeSettings` → `LocllmWindow` / `_LocllmWindow*` / `LocllmSettings`；
- 命令：`fcmd llmservew` → `fcmd locllmw`（`pyproject` 入口、工具注册、静态清单同步）；
- CLI `llmserve` 不改名，二者职责分离：`llmserve` 负责脚本化的启动计划与进程
  生命周期，`locllmw` 负责本机窗口化的本地 LLM 工作台。

### 2. 五页侧边栏信息架构

侧边栏复用 [ADR 0025](0025-sidebar-page-navigation.md) 的 `SidebarNav`；规划中的
代理 / 视频 / 音频不再单独占「实验室」分页（原占位页已移除），只保留已落地能力：

| 分页 | key | 内容 | 状态 |
|---|---|---|---|
| 概览 | `overview` | 系统信息（规格 + GPU / CPU / 内存负载格图、显存 / 交换副条 + 「运行中的模型」各自实时性能）、智能推荐（见 [ADR 0028](0028-llmw-overview.md)） | 已落地 |
| 模型 | `models` | 浏览列表 + 行内下载 / 转换 / 量化（整合原 llmdownw，见 [ADR 0030](0030-llmw-models-page.md)） | 已落地 |
| 运行 | `run` | 「文本 / 图像」分页；文本页使用 llama.cpp 启动参数（列出全部 LLM，含对话 / 编程 / 推理），图像页签与文本同构（加载方式方块 / 运行选项胶囊、高级参数折叠区、只读启动命令预览、自定义参数保存 / 填入）；顶部模型下拉选择（已启动项绿色标记、默认上次运行模型、按模型持久化参数）+ 启动 / 停止 / 重启按钮、整合档位与调优的运行模式方块（速度红 / 均衡蓝 / 长上下文 128K 绿 / 超长上下文 192K 琥珀 / 省显存灰）、带说明的 KV 方块选项、启动参数、启动命令预览、自定义启动参数与保存 / 填入、画图服务启停对齐 LLM 模型卡片（见 [ADR 0040](0040-llmw-paint-in-chat.md)） | 已落地 |
| 对话 | `chat` | 服务选择、流式会话、思考过程、图片附件（整合原 llmchatw，见 [ADR 0029](0029-llmw-chat-page.md)）；「画图」开关 + 画图配置（sd.cpp，见 [ADR 0040](0040-llmw-paint-in-chat.md)） | 已落地 |
| 设置 | `settings` | 存储卡片（模型目录）、推理引擎（llama.cpp）卡片（引擎目录 / 已安装引擎，位于存储下方）、sd.cpp 引擎卡片（与推理引擎同构：安装 / 设为默认；画图 / 视频 / 音频共用一张卡与一个默认 tag）、下载与转换参数（见 [ADR 0031](0031-llm-config-unification.md)） | 已落地 |

约定：

- 运行中的模型数量：运行页对应类别页签（文本 / 图像）用共享
  `PillTabBar` 画半透明圆形数字徽标，侧边栏「运行」页按钮用 `SidebarNav.set_badge` 显示
  总数；画图（sd.cpp）是独立后端，按画图服务存活单独计数。计数口径见
  `_llmw_models.running_usage_counts`（LLM 全部算「文本」，sd.cpp 画图服务算「图像」）。
- 运行页「文本 / 图像」用胶囊页签（共享 `widgets.tab_widget`（内部 `pill_tabs`），`PillTabs` / `PillTabBar`）：`setDrawBase(False)`
  去掉整条基线，`QTabBar` 透明底 + 圆角选中块，页签与内容同底色衔接，不再出现
  页签下方的横条；页签不参与等宽分配，靠左紧凑排列。
- 运行页顶部按钮随模型状态显示启动 / 停止服务，另有「重启服务」按钮（仅运行中可用，
  按当前参数停止后重新启动）；服务名由当前模型或运行中服务自动推导，按钮按模型 /
  服务 / busy 状态自动启用或禁用；不再保留底部操作栏。启动 / 停止 / 重启结果通过
  状态栏和服务日志反馈，不再在操作栏放刷新、浏览器、日志或进度条入口。
- 启动命令直接在参数卡片的只读预览框显示；自定义启动参数在下方输入，另提供
  「保存参数」按模型保存当前表单；「填入当前参数」把与命令预览一致的参数段写入自定义参数框，
  不含可执行文件、模型路径与 `--mmproj`（重复内容不会二次追加）；不再有独立启动计划面板。
- 服务日志与性能测试不占分页：从顶部「帮助 → 服务日志… / 性能测试…」打开非模态对话框
  （服务日志：统一日志组件 + 本次会话缓冲回放；性能测试：被测服务选择 + 场景 / 参数 + 结果表），
  主窗口可继续操作。
- 其余分页日志统一为只读文本 + 「复制 / 清空 / 导出」工具条，标题写明对象（引擎安装日志 /
  转换输出日志 / 量化输出日志 / 下载日志），不再清一色叫「输出日志」。
- 刷新类按钮必须写明对象：刷新模型列表 / 刷新进程状态 / 刷新仓库列表 /
  刷新引擎列表 / 刷新服务列表；硬件快照用「重新检测硬件」，引擎版本用「检测版本」。
- 规划中的能力不再占分页：代理暂无本地推理后端，不保留「实验室」空壳页；视频 /
  音频暂无独立推理后端，也不占运行页签，落地时再新增页签。参数卡内容通过
  `_param_form_for` 可替换：新增后端时换成对应引擎表单，卡片结构不再调整。
- 原「性能测试」独立页并入 `monitor`，用折叠分区保留原有场景选择、参数与
  结果表；分页内容高于窗口时用纵向滚动兜底，不压缩关键控件。

### 3. 同步项

- `pyproject.toml` 入口、`fcmd.cli._manifest_data`（目标模块与描述）、README
  工具表、ADR 0015 / 0024 / 0025 / 0026 的引用统一为 `locllmw`；
- 测试继续由 `tests/apps/llm/test_cli_llmserve.py` 覆盖（CLI `llmserve` 与
  窗口纯逻辑同文件），只更新模块与类名；
- 标题与 `run_window` 文案改为「本地 LLM 服务」。

## 验证

- 工具发现与清单：`locllmw` 条目指向 `fcmd.apps.llm.locllmw`；`fcmd llmserve`
  行为不变。
- 窗口冒烟：真实 Tk 下创建窗口，导航 key 为
  `overview/models/run/chat/settings`，切页与关闭正常。
- 全量测试：`tests/apps/llm` 与 manifest / GUI 用例通过。

  代理页需要先定义任务编排的数据结构与取消语义，再谈 UI。

  没有对应的本地推理后端，不保留空壳页，落地时再新增分页（导航顺序排在对话之后）。
