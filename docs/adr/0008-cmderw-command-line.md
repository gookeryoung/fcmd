# 0008 cmderw 命令行历史与补全

- 状态：生效（K 批）
- 日期：2026-11-11

## 背景

cmderw 命令行栏已支持执行任意 shell 命令（`subprocess.run(shell=True)`，破坏性命令二次
确认），但没有历史与补全：重复命令只能重敲，长路径靠手输。

## 决策

1. 历史
   - 通过二次确认并开始执行的命令（非空、非纯空白）写入历史；连续重复命令只保留最近一次。
   - 历史持久化到 `CmderSettings.command_history`，上限 200 条，越界从最旧丢弃。
   - 上 / 下键在命令行栏内循环历史；首次按上键时暂存当前草稿，回到最新一条后再按下键
     恢复草稿。Esc 清空输入并收起命令行栏。
   - 历史去重保序（最近的在前），读写均容错：非列表、非字符串项直接忽略。
2. 补全
   - Tab 补全第一个 token：
     - 含路径分隔符或以 `.` / `~` 开头：按当前面板目录（相对路径）或用户主目录展开，
       只补全文件与目录名。
     - 不含分隔符：先匹配当前目录条目，再匹配已知工具命令名（`fcmd` 注册的工具名），
       两者合并去重。
   - 唯一候选：补全到完整 token（目录补结尾分隔符，命令补一个空格）。
   - 多候选：补全公共前缀；仍无法推进时在状态栏列出前 8 个候选与总数，不弹模态框，
     避免打断输入。
   - Shift+Tab 不参与补全；其余按键行为不变。
3. 边界
   - 补全只读文件系统，不执行命令、不展开变量、不做 shell 引号解析。
   - 路径补全结果保留用户已输入的前缀形式（相对仍相对，`~` 仍保留 `~`）。
   - 历史与补全不影响「破坏性命令二次确认」与执行路径。

## 落地状态

- K1：已完成。`CmderSettings.command_history` 持久化（容错 + 去重 + 上限 200），
  执行后置顶，上下键循环与草稿恢复。
- K2：已完成。Tab 补全首个 token：路径候选保留前缀形式、目录补分隔符；命令候选合并
  当前目录条目与 `list_tools()` 工具名，唯一候选补空格，多候选补公共前缀并在状态栏
  提示前 8 项与总数。

## 交接

- 纯逻辑集中在 `_ops`：`normalize_command_history` / `command_history_push` /
  `command_history_step` / `split_command_token` / `completion_mode` / `complete_token`；
  Tk 层（`CmderWindow._command_*`）只负责按键绑定、文件系统候选、状态栏提示与光标。
- 历史按设置文件随窗口关闭保存；若将来需要跨面板共享、模糊搜索或参数补全，另开 ADR。
