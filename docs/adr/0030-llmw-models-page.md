# 0030 locllmw 模型页：整合 llmdownw

- 状态：已落地
- 日期：2026-11-14
- 相关文档：[ADR 0016](0016-llmdown-model-browser.md)、[ADR 0025](0025-sidebar-page-navigation.md)、[ADR 0027](0027-llmw-rename.md)

## 背景

`llmdownw` 是独立的 ModelScope 模型浏览器 / 下载器，已有完整的搜索、类别 /
系列筛选、详情、文件清单、下载队列与本地模型管理。但 `locllmw` 的「模型」页
只能列出本地 GGUF 供启动，用户仍需切到另一个窗口去搜索、下载与管理模型目录。
两边都围绕 `llmenv` 的模型目录工作，却维护两套窗口设置与两套服务状态展示。

## 决策

### 1. 单一浏览页取代独立窗口

模型页只保留「浏览」主页面，不再用嵌套 Notebook 分页：
ModelScope 在线模型列表 + 行内下载 / 转换 / 量化。

浏览页不再提供服务端关键字搜索、类别 / 系列下拉，只保留一组筛选按钮：
适合本机、全部、对话、编程、看图、画图、推理、视频、音频。分类筛选把对应关键字交给
ModelScope 搜索（如 coder / vision / reasoning），「适合本机」按硬件快照与系统
内存估算可承载容量，在当前页按模型体积过滤：GGUF 仓库按名字里的参数量估算单份 Q4
（仓库总大小是 Q2–Q8 多精度之和，直接当整仓体积会把 `Qwen/Qwen3-8B-GGUF` 这类官方
仓库误杀），非 GGUF 仓库仍用接口给出的整仓体积；名称搜索是明确意图，输入关键字时
跳过「适合本机」过滤，保证官方大仓库也能被搜到。服务端按默认排序拉取候选，
展示顺序由下方置顶与评分规则决定。分页进度只在底部状态栏显示「筛选名 · 1/9689 · 共 N 条」，
不再在列表上方堆叠页码、总条数与匹配数。
分页行「上一页」左侧提供加宽的名称过滤框（清除按钮 + 250ms 防抖），按仓库名 /
模型名 / 中文名过滤当前页结果，输入期间不重建列表；只过滤本地展示，不触发新的
服务端请求。过滤框后紧跟排序下拉，切换排序会回到第 1 页并按新排序重新请求；
缓存键包含排序字段，不同排序各自缓存。
切换分类 / 翻页时若上一页请求尚未返回，新请求会排队（只保留最后一次），
避免 chip 已切换但列表仍是旧分类或空列表；浏览过的条目会按 repo 记入
会话内 seen 缓存（上限 600 条），切回「全部 / 适合本机」时与当前页合并，
保证刚在「画图 / 编程 / …」里看到的模型不会一换分类就消失；在线列表按
`(关键字, 页码, 每页条数, 排序)` 做内存 + 磁盘缓存
（`~/.fcmd/cache/llmw-model-list.json`，最多 200 页）：10 分钟内命中直接展示、
不发请求；超过 TTL 先回显旧页再后台刷新，网络失败时仍保留上次结果，
避免每次进入模型页都全量拉取。
列表行标题显示模型名 + 发布方胶囊，副标题只放系列 / 任务；状态（已安装 /
部分下载 / 仅本地 / UD / 不可转换 / 不可量化 / 已转换）用名称行胶囊展示，
不再用禁用按钮承载状态，避免操作按钮扎堆。列表提供来源
（在线 / 已下载 / 全部来源）、发布方过滤、「隐藏无效」开关与「同名折叠」：同名**远程仓库**
只保留已安装或评分最高的代表行并标出同名数量，取消折叠可查看全部；本地目录条目
（``repo`` 里没有 ``/``，如磁盘上的 ``Qwen3.8-27B``）不参与折叠——它不是仓库 id，和同名
官方仓库折在一起会按「已安装优先」选中本地目录，把官方模型从列表里藏掉；分类 / 排序 / 来源 /
发布方 / 隐藏无效 / 同名折叠写入 `llmw.json` 的 `model_view`，下次启动自动恢复；
「画图」分类不依赖单个中文关键字（会漏掉官方仓库），改为并行搜索
`Qwen-Image-2.1` / `Qwen-Image` / `MiniMax-H3-Image` / `FLUX` / `HiDream` /
`Kolors` / `HunyuanImage` / `Stable Diffusion` 后按 repo 去重合并，保证第一页各家族
（尤其是 `Qwen/Qwen-Image-2.1`、`MiniMax/...` 官方仓库）都有代表。
「隐藏无效」默认开启，按 `is_usable_item` 过滤：在线结果要求 `组织/模型` 两段式
repo，且 `StorageSize` 不小于 1 MiB（0 表示接口未给体积，按未知保留），挡掉个人
用户上传的 KB 级空壳仓库；仅本地条目要求目录内确有 `.gguf` / `.safetensors` /
`.ckpt` 等权重文件，或仍有未完成的 `.part`（可继续下载）。只有 README / 配置文件 / 空目录的假模型
不再占列表，状态栏显示本次隐藏数量；默认只显示在线结果，
本地一级目录不混入在线列表。列表行在本地模型目录中已存在时不再显示单独徽标；已全部下载完成的模型
不再显示下载按钮（未完成显示「继续下载」、未安装显示「下载」，点击默认整仓下载、也可改选 UD 等单个量化）；
行内删除按钮移除，删除统一走工具栏「模型管理」对话框；手工目录若只有一级
（如 `<models>/Qwen3.8-27B`）无法确定远程 `<组织>/<模型>`，名称行显示「仅本地」
胶囊且不创建下载按钮，避免对不存在的仓库发起清单请求；不在当前页结果里的
已安装模型也会补入列表（分类筛选只补匹配项），已安装且匹配当前用途分类的
结果置顶，其后按排序下拉选择倒排：默认按下载量，另有按发布时间、更新时间、
星标与综合评分（下载量 60 + 星标 40，对数压缩）。

「适合本机」按单模型体积过滤（GGUF 仓库按单份量化估算），但**已安装模型的同名条目
始终保留**：用户已经在用这个模型，官方同名仓库的整仓体积（原始权重几十 GB）常常超过
显存 / 内存口径的容量估算，若一并过滤，官方可下载项会被整条藏掉（实际要下的只是其中
一部分量化文件）。同名判定用本地模型的名称 / 目录名，不影响其它超容模型。

浏览页的结果列表与概览「智能推荐」同构：每行是一张自定义卡片，只保留模型名、
发布方 / 系列 / 任务、发布时间与体积等关键内容；发布机构从名称行改为发布方
胶囊，发布时间与系列 / 任务同处副标题行；状态胶囊与量化精度胶囊并列展示，
量化精度最多展示 4 个，其余折叠为 `+N` 并在 tooltip 列出；不再用五列表格。点击行内「展开」或双击行，
详细信息直接在行下方就地展开（同一时间只展开一行），列表保留整页宽度；
详情本身再分页：「详细信息」放元数据，「文件列表」放仓库文件（路径 + 大小 + **下载状态**，
状态行给合计大小与「已下载 N / 未下载 M」），切换到该页签时才后台读取；文件状态只看本地
文件系统：完整文件「已下载」、「`<文件>.part`」「部分下载」、否则「未下载」，文件列表
重新展开 / 下载完成时只刷新状态列，不重拉在线清单；文件可 Ctrl / Shift 多选后点
「下载所选」单独拉取，右侧「下载全部」只补清单里尚未下载完的文件（已下载的跳过、
`.part` 继续续传，全部下完后按钮禁用），两者都不受设置里的包含 / 排除掩码影响
（下载 VAE / 文本编码器等单个文件不必整仓下载），
文件清单在第一次切到该页签时才后台读取（失败可重试），保持展开内容紧凑、不拖慢展开。
详情分页直接用共享的 `tab_widget(..., object_name="RowTabs")`（`RowTabs` / `PillTabBar`，与运行页同一套
外观）：没有页签上方的分隔线与 QTabBar 整条基线；页签与内容、文件表都跟行卡同底色
（`QTabWidget#RowTabs` 及其内部 `QStackedWidget` 置透明，`QTableWidget#ModelFiles`
去底色 / 边框 / 交替行色），不会在行卡里露出一块窗口底色的「第二个盒子」。
筛选条与结果列表不再各包一层
Card，只保留结果行的卡片边框；QTabWidget 内容区改为无边透明，卡片内表格也去掉
自带边框，避免「面板外再套线框」的双层边框。

### 2. GGUF 启动列表移到「运行」页

模型页的职责收敛为「获取与管理模型文件」，原先占用模型页的本地 GGUF 列表
（能力标签、显存适配、服务名联动）移到「运行」页顶部，与启动参数、操作栏
组成完整的「选模型 → 调参 → 启动」链路。这样模型页单一浏览页与用户要求一一对应，
不再把「可启动模型」和「已下载目录」混在同一棵树里。

### 3. 页面类独立，避免与宿主状态冲突

- 新增 `_llmw_models.py` 的 `_ModelBrowserPage`，持有自己的控件、队列、
  后台任务与轮询；`locllmw` 只负责创建它并调用 `settings_dict()` / `close()`。
- 下载设置从 `~/.fcmd/ui/llmdownw.json` 迁入 `llmw.json` 的 `download` 字段
  （`source / workers / verify / include / exclude`），非法值逐项回退默认；
  独立「下载」子页已移除，参数改由设置页维护。模型目录统一由
  `_llmconfig.models_dir` 提供，下载直接落盘，不保存第二份目录来源。
  下载源默认「自动测速」（与 CLI 的 `auto` 一致：两源实测吞吐选优并保留兜底源），
  并发默认 8、上限 8；旧配置里固定 ModelScope 且没有 `source_probe` 标记时一次性迁到
  自动测速，避免升级后仍被单源限速。选源结果（源名 + 各源实测吞吐 + 兜底源）写入服务日志
  与状态栏，便于和 CLI 对照排查速度差异。
  支持多模型并行下载：默认同时 2 个（`download.parallel` 可设 1–4），达到上限后新任务排队、
  有空位自动开始；同一仓库不会重复入队。每个任务的 workers 按 `workers // parallel` 分摊
  （至少 2），避免总连接数翻倍。底部进度条汇总所有任务的总大小 / 总速度 / 排队数，停止按钮
  一次停止全部下载，关窗确认按任务数提示。
- 浏览列表每个结果行提供「下载」按钮：点击后读取仓库文件清单，默认整仓下载全部文件
  （配置 / 分词器 / LoRA 等一并拉取，避免漏项）；弹窗第一项固定为
  「全部文件（整仓，避免漏项）」且默认选中，需要时也可改选单个量化
  （如 `UD-Q4_K_XL · 18.6 GB · 动态`），只拉取该量化的分片、配套 mmproj 与同仓库
  VAE / CLIP / T5 / 文本编码器组件（按父目录 / 文件名识别角色，未量化的主模型与
  LoRA 不随量化拉取）。`llmdown` 同步提供
  `--quant` / `--file`（未指定时同样整仓下载），保留 `--include/--exclude` 兼容旧用法，
  `--all-quants` 仅为兼容开关。
  UD 动态量化保留文件名原标签（`UD-Q4_K_XL`），档位匹配按 `Q4_K` 族兼容 `XL`；
  动态量化的 GGUF 元数据为基础类型，不再触发文件名与元数据不一致提示。
  下载结束（成功 / 失败 / 停止）后统一重扫本地模型目录，成功的仓库随即切到「已安装 / 已下载」
  状态；扫描进行中收到的新请求会排队，当前扫描结束后立即重扫，避免停留在下载前的旧快照。
  全部文件下载成功后写入模型目录内的 `.fcmd-download.json`（每个文件的大小 / sha256 与完成时间），
  启动扫描时若记录里的文件都在且大小一致即判定已完成，忽略其它残留 `.part`；最终文件旁的同名
  `.part` 一律视为遗留分片（不计数、不算未完成），重下时顺手清理，避免下次启动仍显示下载中。
  目录里仍有 `.part` 的行显示「继续下载」并在名称下方显示已下载进度；
  行内不再提供「删除」，删除统一走工具栏「模型管理」对话框：二次确认后删除本地模型目录并清理该仓库的
  量化选择 / 上次启动记录；对话框列出全部本地模型目录并标出
  完整 / 未完成（`.part` 数），支持多选移除、清理选中或全部未完成下载、清理空
  目录与模型列表缓存，避免长期使用后目录和缓存膨胀；
  已安装且包含 HF safetensors 的模型额外显示「转换」按钮，转换完成后变为
  名称行显示「已转换」胶囊，不再提供按钮。进度条固定在列表底部右侧，同一时间只允许一个下载或转换任务。
  关窗时若仍在下载，先弹二次确认；确认后置停止事件，已下载部分保留 `.part`。

### 4. 移除独立工具 `llmdownw`

- 删除 `src/fcmd/apps/llm/llmdownw.py`；
- 删除 `pyproject.toml` 入口、`_schema` GUI 工具集合与静态清单条目；
- 测试文件改为 `test_llmw_models.py`，保留纯逻辑（格式化 / 过滤 / 排序 /
  增量同步 / 打开路径）并覆盖设置字典与「工具已移除」断言；
- README 工具表移除 `llmdownw`，说明并入 `locllmw`。

### 5. 转换参数并入设置，量化改为行内操作

- 删除独立转换窗口与模型页的「转换」子页；转换精度 / 引擎 tag / 解释器 /
  转换脚本 / 覆盖开关移入设置页的「模型转换」卡片，保存到 `llmw.json` 的
  `convert` 字段，修改后自动保存。「引擎 tag」是可编辑下拉框（可挑已装引擎或填自定义
  tag），旁边「查看支持的架构…」读取当前转换脚本的 `conversion/` 注册表，用于判断某个
  架构（如 `WeMMVideoForConditionalGeneration`）能否转换；不支持时可在「转换脚本」指定
  支持它的自定义脚本 / 源码包，或直接下载官方 GGUF。
- 可转换模型在浏览列表行内提供「转换」按钮；默认输出为
  `<models_dir>/converted/<源目录名>/<源目录名>.gguf`，输出已存在时按钮显示
  「已转换」并禁用。diffusers 多组件目录（如含 `model_index.json` 的
  Qwen-Image 管线）不属于单目录 HF transformers 模型，按钮显示「不可转换」
  并在 tooltip 说明原因。
- 量化不再单独分页：本地全量精度 GGUF 所在行提供「量化」按钮，点击后弹出
  精度选项（`llmqnt.QUANT_TYPES`），选中后按默认输出目录执行一次量化；
  已是量化版本的行把精度标签（如 `Q4_K_M`）与系列 / 任务备注并列放在名称下方，
  使用小号紧凑样式；没有可量化 GGUF 的本地行显示「不可量化」胶囊。转换与量化都调用 `llmconvert` / `llmqnt` 的核心函数。
- 量化菜单会按仓库已有精度做状态标注：已量化的精度显示为勾选、置灰并附
  「（已量化）」，不可再次触发；`start_quantize` 同样做防御性拦截，避免绕过
  菜单重复执行同一精度。

### 6. 量化模型快捷启动

- 仓库内已有量化 GGUF 时，结果行额外提供「启动服务」按钮（主操作样式）。
  点击后弹出精度菜单（多个精度）或直接启动（只有一个精度）；选中后切到
  「运行」页并复用运行页的模型选择 / 启动逻辑，不在模型页复制启动参数。
- 默认精度按持久化顺序回退：`llmw.json` 的 `quant_choice[<仓库>]`（用户上次
  通过快捷启动或运行页启动过的量化精度）→ `last_model` 命中的文件 → 该仓库
  第一个量化文件。当前默认精度在精度标签上注明「· 上次启动」，并带 tooltip 说明。
- `quant_choice` 以仓库（`组织/模型`，大小写不敏感）为键、精度短标签为值；
  运行页每次启动实际量化模型时也会记录，转换产物目录（`converted/`）无法归属
  仓库时不写入。快捷启动按钮在模型 / 启动任务进行中禁用，命中运行中模型时
  只切页提示「已在运行」，不重复拉起进程。

### 7. 手动更新与缓存存储选型

- 浏览页顶部筛选条右侧提供「更新模型」：强制绕过列表缓存拉取当前页，并重新扫描
  本地模型目录；成功后状态栏常驻「更新于 `YYYY-MM-DD HH:MM`」，时间写入
  `llmw.json` 的 `models_updated_at`，重启后仍显示上次更新时间。
- 「更新模型」右侧提供「导入模型」：默认支持导入 `.gguf` 单文件或模型文件夹。
  单个 GGUF 落到 `<models_dir>/<文件名去后缀>/<文件名>`，文件夹落到
  `<models_dir>/<文件夹名>` 并保留内部结构；已在模型目录内的源路径拒绝导入。
  目标已存在时先确认再覆盖同名文件 / 合并目录，复制在线程池执行并复用状态栏
  加载条；完成后重扫本地模型。
- 选择文件夹时先识别类型并在确认框注明：
  - HF safetensors（tensors）→ 「导入并转换」/「仅导入」；
  - GGUF → 「导入」（可直接启动）；
  - GGUF + tensors → 「导入并转换」/「仅导入」；
  - diffusers 多组件（`model_index.json`）→ 警告后「仍然导入」/ 取消；
  - 未识别 → 警告后「仍然导入」/ 取消。
  「导入并转换」在重扫完成、确认该仓库可转换后直接复用行内转换流程；
  不可转换 / 未知类型只登记文件，不自动启动其它动作。
- 列表缓存继续使用**内存 LRU + 单个 JSON 文件**，暂不引入 SQLite。当前规模
  （最多 200 页 / 约 4000 条摘要、单文件几 MB）下，JSON 一次读取 + 内存命中
  已在毫秒级；瓶颈在网络请求而不是本地查询。SQLite 的收益要到需要跨页 / 离线
  全文检索、按字段增量更新或并发写入时才明显，代价是表结构、迁移与锁竞争。
- 何时重新评估：需要「过滤全部缓存页」而不是只过滤当前页；缓存摘要超过约
  1 万条或 5 MB；需要按仓库 / 精度 / 下载状态做索引查询；缓存成为下载 / 量化
  状态的事实来源。若切换，建议表 `model_pages(key TEXT PRIMARY KEY, keyword,
  page, page_size, sort, at, total, payload)` + 需要检索时拆 `model_summaries`
  并给 `repo / name` 建索引，保留同样的 TTL 与陈旧先回显语义。
