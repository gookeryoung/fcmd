# 0030 locllmw 模型页：整合 llmdownw

- 状态：已落地
- 日期：2026-11-14
- 相关文档：[ADR 0016](0016-llmdown-model-browser.md)、[ADR 0025](0025-sidebar-page-navigation.md)、[ADR 0027](0027-locllmw-rename.md)

## 背景

`llmdownw` 是独立的 ModelScope 模型浏览器 / 下载器，已有完整的搜索、类别 /
系列筛选、详情、文件清单、下载队列与本地模型管理。但 `locllmw` 的「模型」页
只能列出本地 GGUF 供启动，用户仍需切到另一个窗口去搜索、下载与管理模型目录。
两边都围绕 `llmenv` 的模型目录工作，却维护两套窗口设置与两套服务状态展示。

## 决策

### 1. 单一浏览页取代独立窗口

模型页只保留「浏览」主页面，不再用嵌套 Notebook 分页：
ModelScope 在线模型列表 + 行内下载 / 转换 / 量化。

浏览页不再提供服务端关键字搜索、类别 / 系列下拉，只保留一组筛选按钮：
适合本机、全部、对话、编程、看图、推理、视频、音频。分类筛选把对应关键字交给
ModelScope 搜索（如 coder / vision / reasoning），「适合本机」按硬件快照与系统
内存估算可承载容量，在当前页按整仓体积过滤；服务端按默认排序拉取候选，
展示顺序由下方置顶与评分规则决定。分页进度只在底部状态栏显示「筛选名 · 1/9689 · 共 N 条」，
不再在列表上方堆叠页码、总条数与匹配数。
分页行「上一页」左侧提供加宽的名称过滤框（清除按钮 + 250ms 防抖），按仓库名 /
模型名 / 中文名过滤当前页结果，输入期间不重建列表；只过滤本地展示，不触发新的
服务端请求。过滤框后紧跟排序下拉，切换排序会回到第 1 页并按新排序重新请求；
缓存键包含排序字段，不同排序各自缓存。
在线列表按 `(关键字, 页码, 每页条数, 排序)` 做内存 + 磁盘缓存
（`~/.fcmd/cache/locllmw-model-list.json`，最多 200 页）：10 分钟内命中直接展示、
不发请求；超过 TTL 先回显旧页再后台刷新，网络失败时仍保留上次结果，
避免每次进入模型页都全量拉取。
列表行在本地模型目录中已存在时不再显示单独徽标，行内下载按钮变为绿色
「✓ 已安装」且不可点击；不在当前页结果里的
已安装模型也会补入列表（分类筛选只补匹配项），已安装且匹配当前用途分类的
结果置顶，其后按排序下拉选择倒排：默认按下载量，另有按发布时间、更新时间、
星标与综合评分（下载量 60 + 星标 40，对数压缩）。

浏览页的结果列表与概览「智能推荐」同构：每行是一张自定义卡片，只保留模型名、
发布时间、发布方 / 系列 / 任务与体积等关键内容；发布机构不再占用名称行，
名称后用浅色小字标注「发布 YYYY-MM-DD」；不再用五列表格。点击行内「展开」或双击行，
详细信息直接在行下方就地展开（同一时间只展开一行），列表保留整页宽度；
浏览页不展示 README 与文件清单，保持展开内容紧凑。筛选条与结果列表不再各包一层
Card，只保留结果行的卡片边框；QTabWidget 内容区改为无边透明，卡片内表格也去掉
自带边框，避免「面板外再套线框」的双层边框。

### 2. GGUF 启动列表移到「运行」页

模型页的职责收敛为「获取与管理模型文件」，原先占用模型页的本地 GGUF 列表
（能力标签、显存适配、服务名联动）移到「运行」页顶部，与启动参数、操作栏
组成完整的「选模型 → 调参 → 启动」链路。这样模型页单一浏览页与用户要求一一对应，
不再把「可启动模型」和「已下载目录」混在同一棵树里。

### 3. 页面类独立，避免与宿主状态冲突

- 新增 `_locllmw_models.py` 的 `_ModelBrowserPage`，持有自己的控件、队列、
  后台任务与轮询；`locllmw` 只负责创建它并调用 `settings_dict()` / `close()`。
- 下载设置从 `~/.fcmd/ui/llmdownw.json` 迁入 `locllmw.json` 的 `download` 字段
  （`source / workers / verify / include / exclude`），非法值逐项回退默认；
  独立「下载」子页已移除，参数改由设置页维护。模型目录统一由
  `_llmconfig.models_dir` 提供，下载直接落盘，不保存第二份目录来源。
- 浏览列表每个结果行提供「下载」按钮：点击后先读取仓库文件清单并按量化聚合，
  只有一个量化时直接下载，多个量化时弹出选择（如 `UD-Q4_K_XL · 18.6 GB · 动态`），
  只拉取该量化的分片与配套 mmproj；不再默认整仓下载。`llmdown` 同步提供
  `--quant` / `--file` / `--all-quants`，保留 `--include/--exclude` 兼容旧用法。
  UD 动态量化保留文件名原标签（`UD-Q4_K_XL`），档位匹配按 `Q4_K` 族兼容 `XL`；
  动态量化的 GGUF 元数据为基础类型，不再触发文件名与元数据不一致提示。
  目录里仍有 `.part` 的行显示「继续下载」并在名称下方显示已下载进度，
  已安装且包含 HF safetensors 的模型额外显示「转换」按钮，转换完成后变为
  「已转换」。进度条固定在列表底部右侧，同一时间只允许一个下载或转换任务。
  关窗时若仍在下载，先弹二次确认；确认后置停止事件，已下载部分保留 `.part`。

### 4. 移除独立工具 `llmdownw`

- 删除 `src/fcmd/apps/locllm/llmdownw.py`；
- 删除 `pyproject.toml` 入口、`_schema` GUI 工具集合与静态清单条目；
- 测试文件改为 `test_locllmw_models.py`，保留纯逻辑（格式化 / 过滤 / 排序 /
  增量同步 / 打开路径）并覆盖设置字典与「工具已移除」断言；
- README 工具表移除 `llmdownw`，说明并入 `locllmw`。

### 5. 转换参数并入设置，量化改为行内操作

- 删除独立转换窗口与模型页的「转换」子页；转换精度 / 引擎 tag / 解释器 /
  转换脚本 / 覆盖开关移入设置页的「模型转换」卡片，保存到 `locllmw.json` 的
  `convert` 字段，修改后自动保存。
- 可转换模型在浏览列表行内提供「转换」按钮；默认输出为
  `<models_dir>/converted/<源目录名>/<源目录名>.gguf`，输出已存在时按钮显示
  「已转换」并禁用。diffusers 多组件目录（如含 `model_index.json` 的
  Qwen-Image 管线）不属于单目录 HF transformers 模型，按钮显示「不可转换」
  并在 tooltip 说明原因。
- 量化不再单独分页：本地全量精度 GGUF 所在行提供「量化」按钮，点击后弹出
  精度选项（`llmqnt.QUANT_TYPES`），选中后按默认输出目录执行一次量化；
  已是量化版本的行把精度标签（如 `Q4_K_M`）与系列 / 任务备注并列放在名称下方，
  使用小号紧凑样式；没有可量化 GGUF 的本地行显示「不可量化」。转换与量化都调用 `llmconvert` / `llmqnt` 的核心函数。
- 量化菜单会按仓库已有精度做状态标注：已量化的精度显示为勾选、置灰并附
  「（已量化）」，不可再次触发；`start_quantize` 同样做防御性拦截，避免绕过
  菜单重复执行同一精度。

### 6. 量化模型快捷启动

- 仓库内已有量化 GGUF 时，结果行额外提供「启动服务」按钮（主操作样式）。
  点击后弹出精度菜单（多个精度）或直接启动（只有一个精度）；选中后切到
  「运行」页并复用运行页的模型选择 / 启动逻辑，不在模型页复制启动参数。
- 默认精度按持久化顺序回退：`locllmw.json` 的 `quant_choice[<仓库>]`（用户上次
  通过快捷启动或运行页启动过的量化精度）→ `last_model` 命中的文件 → 该仓库
  第一个量化文件。当前默认精度在精度标签上注明「· 上次启动」，并带 tooltip 说明。
- `quant_choice` 以仓库（`组织/模型`，大小写不敏感）为键、精度短标签为值；
  运行页每次启动实际量化模型时也会记录，转换产物目录（`converted/`）无法归属
  仓库时不写入。快捷启动按钮在模型 / 启动任务进行中禁用，命中运行中模型时
  只切页提示「已在运行」，不重复拉起进程。

### 7. 手动更新与缓存存储选型

- 浏览页顶部筛选条右侧提供「更新模型」：强制绕过列表缓存拉取当前页，并重新扫描
  本地模型目录；成功后状态栏常驻「更新于 `YYYY-MM-DD HH:MM`」，时间写入
  `locllmw.json` 的 `models_updated_at`，重启后仍显示上次更新时间。
- 「更新模型」右侧提供「导入模型」：默认支持导入 `.gguf` 单文件或模型文件夹。
  单个 GGUF 落到 `<models_dir>/<文件名去后缀>/<文件名>`，文件夹落到
  `<models_dir>/<文件夹名>` 并保留内部结构；已在模型目录内的源路径拒绝导入。
  目标已存在时先确认再覆盖同名文件 / 合并目录，复制在线程池执行并复用状态栏
  加载条；完成后重扫本地模型。
- 选择文件夹时先识别类型并在确认框注明：
  - HF safetensors（tensors）→ 「导入并转换」/「仅导入」；
  - GGUF → 「导入」（可直接启动）；
  - GGUF + tensors → 「导入并转换」/「仅导入」；
  - diffusers 多组件（`model_index.json`）→ 警告后「仍然导入」/ 取消；
  - 未识别 → 警告后「仍然导入」/ 取消。
  「导入并转换」在重扫完成、确认该仓库可转换后直接复用行内转换流程；
  不可转换 / 未知类型只登记文件，不自动启动其它动作。
- 列表缓存继续使用**内存 LRU + 单个 JSON 文件**，暂不引入 SQLite。当前规模
  （最多 200 页 / 约 4000 条摘要、单文件几 MB）下，JSON 一次读取 + 内存命中
  已在毫秒级；瓶颈在网络请求而不是本地查询。SQLite 的收益要到需要跨页 / 离线
  全文检索、按字段增量更新或并发写入时才明显，代价是表结构、迁移与锁竞争。
- 何时重新评估：需要「过滤全部缓存页」而不是只过滤当前页；缓存摘要超过约
  1 万条或 5 MB；需要按仓库 / 精度 / 下载状态做索引查询；缓存成为下载 / 量化
  状态的事实来源。若切换，建议表 `model_pages(key TEXT PRIMARY KEY, keyword,
  page, page_size, sort, at, total, payload)` + 需要检索时拆 `model_summaries`
  并给 `repo / name` 建索引，保留同样的 TTL 与陈旧先回显语义。

## 验证

- 真实 Qt 冒烟：`locllmw` 打开后模型页直接显示浏览列表；加载 ModelScope 列表
  （自定义行），展开行后就地显示详情元数据，行内「下载」/「转换」/「量化」按钮
  在底部右侧更新进度；设置页修改下载 / 转换参数后自动保存。
- 转换 / 量化真实跑通：在浏览列表对可转换模型点击「转换」，产物落
  `<models_dir>/converted/<源目录名>/`，按钮变为「已转换」；再对含全量精度 GGUF
  的模型点击「量化」选择精度，产物落 `<models_dir>/converted/`，名称下方出现精度标签。
- 快捷启动：准备两个量化精度的本地仓库，点击「启动服务」默认命中
  `quant_choice` / 上次启动精度，菜单切换其它精度后运行页启动对应 GGUF；
  再次启动同一精度时精度标签仍标注「上次启动」。
- 手动更新：点击「更新模型」会绕过新鲜缓存并重扫本地；成功后状态栏出现
  「更新于 …」，重启窗口仍保留该时间。
- 导入：分别导入单个 GGUF 与包含 HF safetensors 的文件夹，目标目录规整为
  一级仓库布局；文件夹确认框显示 tensors / GGUF / diffusers / unknown 类型，
  tensors 可选择「导入并转换」；重复导入弹确认，成功后列表出现已安装标识。
- 全量测试与 `make check-fast` 通过。

## 交接

- 「浏览」与「已安装」的联动（双击已安装模型回到浏览详情）已保留；量化模型的
  「启动服务」快捷按钮只负责选精度与发请求（`ServeRequested` → 窗口切到运行页），
  实际启动仍由运行页 `start_model` 完成；不要在这里复制参数拼装逻辑。
- 下载设置由设置页自动保存到 `locllmw.json` 的 `download` 字段；浏览页每次点击下载时
  读取最新参数，不再恢复独立下载页。
