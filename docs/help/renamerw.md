# renamerw 批量重命名帮助

renamerw 用「规则流水线」批量生成新文件名：先添加目标，再按顺序堆叠规则，最后在预览里确认「旧名 → 新名」后执行。规则可导出为 JSON 复用；执行采用两阶段改名，并支持本次运行内撤销。

本文对应 `fcmd renamer` 与 GUI 中的批量重命名窗口，需求与设计见 [ADR 0014](../adr/0014-batch-renamer.md)。

## 界面分区

| 分区 | 内容 | 说明 |
|---|---|---|
| 目标 | 添加文件 / 添加目录 / 移除选中 / 清空 | 目录可勾选「递归子目录」「包含目录」；「计数器排序」决定计数器的编号顺序 |
| 规则 | 表单 + 规则表 | 规则自上而下依次执行；双击规则表中的行可回填表单再「更新选中」 |
| 预览 | 刷新预览 / 执行改名 / 撤销上次 | 只执行状态为「可执行」的行，执行前会二次确认 |

规则表按批量顺序生效：名称与扩展名分开处理，扩展名不会被误改；目录始终按名称处理（作用域选「扩展名」对目录无效）。

## 规则类型

| kind | 作用 | 必填字段 | 关键行为 |
|---|---|---|---|
| `replace` | 正则替换 | `pattern` | 模板用 `\1` 或 `\g<name>` 引用捕获组；`occurrence` 为 0 时替换全部 |
| `reorder` | 按捕获组重排 | `pattern`、`replacement` | 模板用 `{0}`/`{1}`/`{name}`；未匹配时原样返回 |
| `move` | 把匹配文本搬到锚点 | `pattern` | 匹配文本从原位置移除后整体插入锚点；锚点文本必须存在 |
| `insert` | 插入字面文本 | `text` | 在锚点插入固定文本，不参与正则 |
| `case` | 大小写转换 | `mode` | 模式：`keep` / `lower` / `upper` / `title` / `sentence` |
| `sequence` | 追加计数器 | — | 按批内序号生成编号；`text` 为分隔符 |

公共字段：

- `field`：`stem`（名称，默认）或 `ext`（扩展名）。
- `occurrence`：0 表示全部匹配；N 表示只处理第 N 个匹配，越界不报错。
- `anchor`：`start` / `end` / `before` / `after` / `index`；`before`、`after` 需要 `anchor_text`，`index` 使用 `position`（负数从末尾算）。
- `start` / `step` / `digits`：计数器起始值、步长与位数，位数不足时左侧补零。

生成的新名称会去掉首尾空白，且不允许为空、`.`、`..`、路径分隔符、`< > : " | ? *`，长度上限 255 字符；不满足时预览标记「非法」。

## 典型示例

以下示例同时以 JSON 文件放在 [examples/](examples/) 下，可直接通过「帮助 → 载入规则…」导入；也可以打开「帮助 → 使用帮助」，双击示例一键写入规则表。

### 1. 照片 / 扫描件补零编号

`IMG_1.jpg → 照片_001.jpg`：先去掉原有前缀与编号，再按批内顺序追加三位计数器。

```json
[
  {"kind": "replace", "pattern": "^IMG_", "replacement": "照片_"},
  {"kind": "replace", "pattern": "_\\d+$"},
  {"kind": "sequence", "anchor": "end", "text": "_"}
]
```

完整文件：[01-photo-sequence.json](examples/01-photo-sequence.json)。计数器位数默认 3；源文件若含多位编号（如 `IMG_10`），按名称排序会排在 `IMG_2` 之前，建议改用补零后的源名或按修改时间排序。

### 2. 剧集规范化（SxxExx）

`Show.01x02.1080p.mkv → Show - S01E02.mkv`：捕获剧名、季号、集号后重排，并丢弃发布标记。

```json
[
  {
    "kind": "reorder",
    "pattern": "^(?P<show>.+?)\\.(?P<season>\\d{2})x(?P<episode>\\d{2})\\..*$",
    "replacement": "{show} - S{season}E{episode}"
  }
]
```

完整文件：[02-tv-episode.json](examples/02-tv-episode.json)。reorder 只搬运捕获内容、不做数值补零，因此示例要求源文件名使用两位季号；遇到 `1x02` 这类写法，可先统一成两位再执行。

### 3. 日期片段搬到前面

`会议纪要-20240501.docx → 20240501_会议纪要.docx`：交换标题与 8 位日期。

```json
[
  {
    "kind": "reorder",
    "pattern": "^(?P<title>.+?)[-_](?P<date>\\d{8})$",
    "replacement": "{date}_{title}"
  }
]
```

完整文件：[03-date-prefix.json](examples/03-date-prefix.json)。需要统一分隔符时，可在其后追加一条 `replace`（如 `[_-]` → `_`）。

### 4. 清理噪声 + 大小写统一

`my  file (1).TXT → My_File.txt`：去括号内容、空格转下划线、名称标题式、扩展名小写。

```json
[
  {"kind": "replace", "pattern": "\\s*[(\\[][^)\\]]*[)\\]]"},
  {"kind": "replace", "pattern": "\\s+", "replacement": "_"},
  {"kind": "case", "mode": "title"},
  {"kind": "case", "field": "ext"}
]
```

完整文件：[04-cleanup-case.json](examples/04-cleanup-case.json)。`case` 的默认模式即小写，所以最后一条只需指明作用域为扩展名。

## 执行与撤销

预览状态含义：

| 状态 | 含义 |
|---|---|
| 可执行 | 名称会变化，且目标未被占用、批内不重名 |
| 未变化 | 规则执行后名称不变 |
| 非法 | 生成名称为空、含路径分隔符或非法字符、超长，或规则运行时出错 |
| 冲突 | 批内重名，或目标名称已存在 |

点「执行改名」会先刷新预览并二次确认，只执行「可执行」项；改名采用两阶段（先改成临时名再落到目标名），中途失败会回滚已处理项。「撤销上次」只针对本次运行的最后一轮改名，且要求当前文件名仍与改名结果一致；程序退出后不保留撤销历史。

## 常见问题

- **顺序不符合预期**：「计数器排序」默认按名称做字符串排序（`1, 10, 2`）；需要自然顺序时，把源文件补零命名或按修改时间排序。
- **提示锚点文本未找到**：`move` / `insert` 使用 `before`、`after` 锚点时必须填写在名称中确实存在的 `anchor_text`。
- **扩展名没变**：检查作用域是否选中「扩展名」；目录的扩展名规则不生效。
- **全部冲突**：确认目标文件不在同一目录下重名；批量加后缀或计数器通常可以避免。
- **想复用规则**：用「帮助 → 保存规则…」导出 JSON，下次「帮助 → 载入规则…」导入；内置示例见 [examples/](examples/)。
