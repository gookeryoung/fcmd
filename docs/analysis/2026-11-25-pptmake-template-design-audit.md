# pptmake 模板设计质量审计与改进方案

- 日期：2026-11-25
- 范围：`src/fcmd/apps/pptmake/`（模型、令牌、版式引擎、PPTX 导出/导入、预览、Qt 编辑器）
- 性质：只读审计 + 方案，不改代码
- 结论一句话：**pptmake 目前是一套「用矩形和文本框在空白版式上画 PPT」的绘制器，而不是一套「可被 PowerPoint 识别与复用」的演示模板**；最大的专业性差距不在配色好不好看，而在母版/版式/占位符、主题部件、字段化页码、原生表格图表这四件事上完全缺位。

## 0. 审计方法与口径

- 设计坐标：96 单位 / 英寸，16:9 = 1280×720，4:3 = 960×720；换算关系 `1 单位 = 0.75pt`（`_design.py:1-7`、`_core.py:110-118`、`_pptx.py:35-36`）。
- 下文所有字号、行高、位置均由代码常量与绘制逻辑确定性换算得出；标注 `文件:行` 的是代码证据。
- 本次未在当前工作区执行脚本（工作区处于未信任状态），因此没有现成 `.pptx` 产物；第 8 节给出可复现的取证命令，任何人可一次导出后逐条核对本文结论（所有结论都是代码路径必然后果，不是观感推测）。

## 1. 现状盘点

### 1.1 模板从哪里来

| 环节 | 实现 | 证据 |
|---|---|---|
| 模板载体 | 自定义 JSON（`*.pptmtpl.json`），schema v3；v1/v2 加载时补默认值，高于 3 拒绝 | `_core.py:97-98`、`_core.py:637-645` |
| 模板内容 | 名称/作者/画幅 + `theme`（6 色、2 字体、装饰、令牌、页脚、页码开关、Logo）+ 13 种版式清单 + 逐页 `slides` | `_core.py:275-315` |
| 模板来源 | `init` 内置示例 / 四套预设 / `import` 现有 PPTX 的「尽力还原」 | `pptmake.py:107-148`、`_pptx.py:377-416` |
| 设计令牌 | 10 级字号、6 项间距、2 项圆角、密度（0.85/1.0/1.2）、装饰强度、字体回退链、4 个语义色 | `_tokens.py:113-184` |
| 版式生成 | 13 个 renderer 输出 5 种图元（Rect / Oval / Line / Picture / Text） | `_design.py:62-134`、`_design.py:1393-1407` |
| 预览/导出 | 同一份 draw list：Qt 画布按比例缩放，PPTX 按 `值/96` 换成英寸 | `_design.py:1475-1499`、`_pptx.py:260-288` |
| 成品输出 | `.pptx`（python-pptx 默认模板 + 空白版式 6） | `_pptx.py:262-275` |

一句话：**模板 = JSON 里的绘制参数，不是 PowerPoint 里的母版**。这决定了后面绝大多数差距。

### 1.2 版式与占位

| 版式 | 内容槽 | 实现 | 原生占位符 |
|---|---|---|---|
| 封面 cover | 标题/副标题/备注 | 固定坐标文本 + 装饰线 | 无 |
| 目录 agenda | 标题/副标题/要点（>4 条自动两列） | 编号圆 + 文本 | 无 |
| 章节 section | 标题/副标题（正则取数字）/首条要点 | 超大编号 + 竖线 | 无 |
| 要点 bullets | 标题/副标题/要点（缩进最多 2 级） | 方标 + 文本，行高 = `min(body×3.5, 可用高度/条数)` | 无 |
| 双栏 two_column | 标题/副标题（`左|右`）/要点对半分 | 两张卡片 | 无 |
| 引用 quote | 标题当金句/副标题当署名 | 大引号 + 文本 | 无 |
| 数据 metrics | 标题 + 3 条 `值|说明` | 3 张卡片 | 无 |
| 时间线 timeline | 标题 + ≤4 条 `阶段|说明` | 横线 + 圆点 | 无 |
| 结尾 closing | 标题/副标题 | 居中文本 + 光斑 | 无 |
| 图片 image | 标题/副标题/≤3 条要点/图片 | 左文右图卡片 | 无 |
| 对比 comparison | 标题/副标题（`A|B`）+ ≤4 条 `维度|A|B` | 手绘表格（矩形+文本+分隔线） | 无 |
| 图表 chart | 标题 + ≤5 条 `标签|数值` | 手绘柱状图（矩形+网格线） | 无 |
| 联系方式 contact | 标题/副标题/≤4 条 `标签|值` | 文本 + 假二维码 3 个方块 | 无 |

全仓 `add_table`、`add_chart`、`placeholder`、`sldNum`、`descr`（alt）零命中：**没有任何一页使用 PowerPoint 的版式、占位符、表格、图表、页码字段、替代文本**（`_pptx.py:212-257`）。

### 1.3 字体、字号、行距

默认字号阶梯（`_tokens.py:117-126`，换算为 pt）：

| 角色 | 设计单位 | 实际 pt | 典型用途 |
|---|---:|---:|---|
| display | 58 | 43.5 | 封面主标题 |
| title | 40 | 30.0 | 页面标题 |
| subtitle | 18 | 13.5 | 副标题 |
| heading | 22 | 16.5 | 卡片标题 |
| body | 20 | **15.0** | 正文/要点 |
| small | 16 | 12.0 | 次要正文、卡片条目、时间线阶段 |
| caption | 13 | **9.75** | 注释、页脚、页码、图表标签 |
| stat | 44 | 33.0 | 数据数字 |
| quote | 34 | 25.5 | 引用 |
| section_number | 124 | 93.0 | 章节编号 |

行距现状：

| 位置 | 行距 | 证据 |
|---|---|---|
| 默认（标题、卡片标题、指标、时间线、对比、图表、联系） | 1.2 | `_design.py:129` |
| 封面/图片主视觉/联系标题 | 1.1 / 1.15 | `_design.py:402`、`911`、`1279` |
| 正文类（要点、双栏、图片正文、联系正文、章节说明） | 1.25 | `_design.py:547/590/668/934/952/1302` |
| 引用 | 1.35 | `_design.py:703` |

其他排印事实：

- `Text.space_after` 字段存在，但**13 个版式没有任何一处设过非 0 值**（`_design.py:130`，全仓 grep 只有 `_pptx.py:148-149` 在消费它）——段距体系实际不存在。
- 要点条目的「行距」不是排版行距，而是**盒子高度**：`line_height = min(body×3.5, 可用高度/条数)`（`_design.py:558-560`）。条目少时 70 单位一行（约 0.73 英寸），条目多时被压到几十单位，行距随机漂移。
- 字号阶梯是绝对值，**不随画幅变化**：4:3（960 宽）与 16:9（1280 宽）共用同一套字号（`_core.py:115-118`、`_tokens.py:117-126`），4:3 上正文的视觉占比大约放大 33%。
- `font_fallback`（4 个中文字体回退）只解析、只回写 JSON，**渲染和导出都不消费**（`_tokens.py:177`，全仓无引用）；PPTX 只写 `latin` 与 `ea` 同名，字体缺失时由 PowerPoint 任意替换。
- 字体只有两个槽（标题/正文），没有字重（light/regular/semibold）、字距、大小写、中西文分离、衬线/无衬线搭配预设。

### 1.4 配色

- 6 个语义槽：背景 / 卡片 / 强调 / 辅助 / 正文 / 次要（`_core.py:208-237`），4 套预设（极光蓝深色、素瓷青浅色、石墨金深色、珊瑚暖浅色），无中性阶（50–900）、无分隔线色、无禁用/悬浮态。
- 描边色在版式里**现场用三种不同公式**混合：`mix_hex(background, muted, 0.28)`（双栏 623）、`0.24`（指标 744、图片 966、图表 1189）、`0.32`（联系 1347/1377）——同类元素深浅不一致。
- 4 个语义色（success/warning/danger/info）在令牌层完整实现、可读写 JSON，但**版式层零引用**（`_tokens.py:158-166`）；数据页与对比页无法表达「好/坏/风险」。
- 没有真正的透明度：所有「半透明」都是 `mix_hex` 把颜色按比例预混成实色（`_core.py:340-346`），叠在卡片或图片上时结果取决于假定底色，无法做渐变、玻璃、图片蒙层。
- 没有对比度校验：`relative_luminance` 只在导入时判断深浅（`_pptx.py:345`），导出前不检查正文/背景、注释/背景是否达到 WCAG AA（4.5:1，大字 3:1）。
- 数据系列色固定 `accent / secondary / accent` 循环（`_design.py:736`、`1217`），没有 6–8 色数据序列。

### 1.5 图文排布

- 只有一种图片版式（左文右图，`_design.py:879-1025`）和全页 Logo（`_design.py:1410-1425`）；没有全出血背景图、双图/三图网格、图文比例可选、圆角/蒙版/描边、文字压图时的 scrim 与对比度保护。
- `Picture` 只有 `x/y/w/h/path/fit` 六个字段（`_design.py:101-111`）：**没有 alt、没有 caption、没有裁剪焦点、没有圆角**。需求卡片 C6 写的「图片（路径 + 填充方式 + alt）」中 alt 并未落地（`docs/requirements/0055-pptmake-editing-experience.md:25`）。
- Logo 固定右上角、尺寸由正文字号推导（`body×4.6 × body×1.9`）；标题框横跨整幅（`width - margin×2`），长标题会与 Logo 在右上角重叠（标题框 y=72 起，Logo y≈48–86）。
- 装饰（光斑/网格/边框/极简）每页都画在背景之上、内容之下，**没有封面/章节/内容页的差异化策略**，深色第 1 页与第 10 页完全同构。

### 1.6 母版、页脚、页码

- 导出以 python-pptx 自带 `templates/default.pptx` 为基底（`site-packages/pptx/api.py:26-43`），只用 `slide_layouts[6]`（空白版式，`_pptx.py:270`），所有内容都是浮动 shape。结果是：
  - PowerPoint 大纲视图里看不到标题与正文；
  - 「重设幻灯片」「版式」对成品无效；
  - 母版里没有本模板的 13 种版式，用户无法在 PowerPoint 里「新建幻灯片」选版式；
  - 默认模板是 4:3 母版，被拉伸到 13.333in 画布，占位符栅格与本模板无关（虽然用了空白版式掩盖）。
- 主题部件未写入：`Presentation()` 之后从未修改 `theme1.xml`，颜色全部以 `srgbClr` 写死在每个 shape/run 上（`_pptx.py:88-101`、`158`），字体写死在 run 上（`_pptx.py:157-159`）。**用户在 PowerPoint 里换主题色/主题字体，整份稿不会联动**。
- 页码是静态文本 `f"{page:02d} / {total:02d}"`（`_design.py:1458`），不是 `a:fld type="slidenum"`；增删页后不会自动更新。
- 页码对**所有页**追加：`export_pptx` 对每页传 `page_number=index`（`_pptx.py:274`），Qt 预览/缩略图同样（`_pptmakew_qt.py:1302/1448`），`_paint_footer` 只判断 `show_page_number`（`_design.py:1436-1472`）——**封面会出现「01 / 13」，章节页、结尾页也不会抑制**。
- 页脚只有一段左对齐文字 + 右侧页码（`_design.py:1443-1472`），没有日期、汇报人、机构、机密等级、来源注等常见页脚槽位。
- 封面自带一套写死的品牌字：「PPT TEMPLATE」「DESIGNED WITH PPTMAKE」「PPTMAKE · 模板」（`_design.py:382/425/437`），与 `theme.footer` 并存，出现双页脚。

### 1.7 表格与图表

- 对比矩阵：背景矩形 + 三列文本 + 行分隔线（`_design.py:1052-1162`）。只是「看起来像表格」，不是 `a:tbl`：不能增删行列、不能套表格样式、不能排序、Excel 数据不联动；只支持 2 个方案列、最多 4 行；没有表头样式、斑马纹、数字右对齐。
- 图表：手绘柱状图（`_design.py:1165-1258`）。
  - 有 5 条横向网格线，但**没有任何 Y 轴刻度数值、没有单位、没有图例、没有坐标轴标题**；
  - 负值画错：`bar_height = max(plot_height × value / max_value, 2)`（`_design.py:1214`），负值也贴底画 2px 小柱；
  - 最多 5 根柱，只能柱状，不能切换折线/饼图/堆叠，不能改数据（导出后是一堆矩形）；
  - 图表页底部还印着「图表占位 · 导出后可在 PowerPoint 中替换为真实图表」（`_design.py:1247-1258`），图片页印着「图片占位 · 导出后在 PowerPoint 中替换」（`_design.py:1013-1025`）——**实现说明直接进入成品**。
- 指标卡只接受 `值|说明`，数值原样当字符串画，没有千分位/百分比/单位/同比趋势/正负语义色（`_design.py:721-774`）。

### 1.8 导出、导入、预览一致性

- 导出**默认不做质量拦截**：`export` 直接渲染（`pptmake.py:236-246`），`validate` 是独立命令，且溢出判断基于 em 估算。
- PPTX 文本框 `auto_size = NONE` + `word_wrap = True` + 四边 margin 全 0（`_pptx.py:127-133`）：没有 shrink-to-fit，文字超了就在框外溢出；编辑时文字贴着框边。
- 要点层级在两条链路口径不同：设计层用 x 偏移模拟缩进（`_design.py:562-593`），PPTX 层只写 `paragraph.level`，没有 `marL/indent/buChar`（`_pptx.py:150`），导出的缩进量与项目符号由 PowerPoint 母版默认值决定，**与预览不一致**，且没有真正的 `buChar/buAutoNum`。
- 预览文本测量是自研 em 估算（`_preview.py:132-197`），Qt 行高按 `pixel_size × (line_spacing - 1.2)` 近似（`_pptmakew_qt.py:242`），与 PowerPoint 的真实排版引擎必然有差异；标题长度>22 字只做一次 0.79 倍缩字（`_design.py:390`），没有多级 fit。
- 导入只保留主题配色/字体 + 段落文本（`_pptx.py:362-416`）：图片、表格、图表、母版、版式、备注全部丢失，所有内容页压成 bullets，首段当标题的规则在真实稿上经常错位。

## 3. 改进方案

### 3.1 三条设计原则

1. **主题原生优先于画得像**：能用母版/版式/占位符/主题色表达的，不再用浮动 shape 模拟。预览可以继续用 draw list，但导出必须落到 PPTX 原生结构。
2. **先有栅格与节奏，再谈装饰**：12 列栅格 + 基线间距 + 段落级行距，13 个版式共用同一套锚点（标题带 / 正文带 / 页脚带），消灭「字号倍数魔法数」。
3. **内容约束前移**：每版式定义 max_bullets / max_chars / title_lines，编辑器实时提示，导出前强制校验；宁可提示精简，也不静默溢出。

### 3.2 P0：排版与文案卫生（不动导出结构，收益立竿见影）

1. **字号阶梯重定**（`_tokens.py`），建议值（设计单位 / pt）：
   - display 64/48、title 48/36、subtitle 28/21、heading 32/24、body 24/18、small 20/15、caption 16/12、stat 56/42、quote 44/33、section_number 168/126。
   - 新增按画幅的展示级系数：`aspect_scale = {"16:9": 1.0, "4:3": 0.92}`，只作用于 display/title/quote/stat/section_number，正文与注释保持 pt 不变（可读性优先）。
   - 迁移：v3 模板加载时保留显式写过的字号，未写过的取新默认；写回升 v4。
2. **行距与段距令牌化**：`line_display 1.1 / line_heading 1.25 / line_body 1.45 / line_caption 1.35`，`space_after_body 0.6×body / space_after_item 0.4×body / space_before_heading 1.0×body`；要点改为真实段落流 + 段距，不再用盒子高度当行距。
3. **品牌与占位文案外置**：`theme.eyebrow`（封面眉标，默认空）、`theme.credit`（封面右下，默认空）、`theme.footer` 单一口径；删除「PPT TEMPLATE / DESIGNED WITH PPTMAKE / PPTMAKE · 模板」与两处「…占位」文字。占位提示作为预览专用图层（`build_draw_list(..., hints=True)`），导出恒为 False。
4. **页码策略**：`page_number` 增加 `hidden_layouts`（默认 cover/section/closing/contact 隐藏）；封面不再出现页码。
5. **统一描边与分隔线令牌**：`tokens.stroke.border`、`tokens.stroke.divider`、`tokens.stroke.width`，13 版式只引用，不再各自 mix。
6. **导出前校验**：`export` 默认跑 validate（溢出 / 最小字号 / 对比度 / 图片缺失），不达标给出逐页清单并要求 `--force` 才继续。
7. **缩进与项目符号对齐**：新增 `tokens.bullet.indent / bullet.size / bullet.char`，预览与 PPTX 同源写入（PPTX 侧写 `marL/indent/buChar`）。

验收：默认稿 13 页无「占位/PPTMAKE/PPT TEMPLATE」字样；封面无页码；正文 ≥18pt、注释 ≥12pt；`validate` 0 溢出；现有设计测试全部按新值更新并通过。

### 3.3 P1：主题与母版

拆成两步，先低风险拿收益：

**P1a 主题部件 + 字段（纯代码，无二进制资源）**

- 导出后对 pptx 包做后处理（`zipfile` + `lxml`），把 `ppt/theme/theme1.xml` 的 `clrScheme` / `fontScheme` 改成本模板的 6 色 + 标题/正文字体（含 `a:ea`），`dk1/lt1` 按亮度分配。
- 写 shape 颜色时优先写 `schemeClr`：把 6 个调色板 hex 映射到 `accent1/2`、`dk1/lt1`、`tx1/bg1`，字体写 `+mj-lt` / `+mn-lt`；不在调色板内的颜色（预混出的描边）仍写 `srgbClr`，后续由 P0 的描边令牌收敛。
- 页码/日期改成 `a:fld`：`slidenum` 用于页码，`datetime` 用于可选日期页脚。
- 兼容：新增 `export --flat` 保留旧行为，供 golden 对照回滚；默认走 `--native`。

验收（解压断言）：`theme1.xml` 的 6 个色值与模板一致；正文 run 使用 `schemeClr`；每页页码是 `a:fld`；PowerPoint 里「设计 → 变体」换主题后整稿联动（人工确认一次）。

**P1b 母版 / 版式 / 占位符（需要一份基础模板资源）**

- 新增 `src/fcmd/apps/pptmake/assets/pptmake-base-16x9.pptx`（及 4:3 版），包含：
  - 主题（同 P1a）、母版装饰（光斑/网格/边框作为母版形状，可用 `showMasterSp` 控制）；
  - 13（后续 20+）个 slideLayout，每个带命名占位符：`title`、`subtitle`、`body`、`picture`、`table`、`chart`、`footer`、`sldNum`、`dt`；
  - 页面尺寸、安全区、页脚带固定。
- 导出改为：打开 base → 按 slide.layout 取对应 layout 新建页 → 向占位符写内容（标题/正文/图片/表格/图表/页码）→ 装饰交给母版；draw list 继续服务预览与 `--flat` 兜底。
- 工程注意：python-pptx 不能凭空创建 layout，只能消费既有模板；因此 base 需要离线制作并作为二进制资源入库，配套一个解压完整性测试（layout 数、占位符名、主题色、页面尺寸），防止资源被误改。
- 风险：二进制资源评审成本、占位符与 13 个 renderer 的映射维护、旧 `--flat` 与新 `--native` 双路径测试量。建议先在 5 个核心版式（cover/section/bullets/image/comparison）打通，再全量铺开。

验收：解压后 `sldLayoutIdLst` 数量 = 版式数；每页存在 `title` 占位符；在 PowerPoint 里「新建幻灯片」能看到 pptmake 版式；大纲视图能读到标题与要点；「重设幻灯片」可用。

### 3.4 P2：原生表格与图表

- **表格**：`comparison` 改为 `add_table`（保留 `维度|A|B` 语法），支持 2–4 个方案列；`tbl.firstRow=True`、`horzBanding=True`，套内置表格样式 GUID；数字列右对齐；行高按内容自适应，超出则提示精简。
- **图表**：`chart` 增加 `chart_type`（bar/line/pie）、`unit`、`value_format`、`show_labels`、`legend`；用 `ChartData` 写入真实数据，系列色取新增 `tokens.chart_palette`（6 色）；补 Y 轴刻度、类别轴标题、单位、数据标签；负值正确落在 0 轴两侧；无数据时显示空状态而不是假柱。
- **指标**：`值|说明|趋势`，趋势支持 `+12%`/`-3pt` 并自动用语义色；数字格式化（千分位/百分比/单位）走令牌。
- 预览：在 draw list 里新增 `Table` / `Chart` 图元（或 preview 侧特判），保证「编辑器里是什么，导出就是什么」；图表预览只需近似，但表格行列/对齐必须与导出同源。
- 验收：导出后双击表格可增删行；双击图表可「编辑数据」并联动；负值渲染正确；表格/图表页无「占位」字样；预览与导出的表格几何 diff ≤1 单位。

### 3.5 P3：版式库与图文规则

按汇报场景价值排序新增版式：

1. 全出血图片封面 / 图片章节页（背景图 + 30–50% scrim + 对比度保护）；
2. 三卡要点（序号或图标）；
3. 流程步骤（4–6 步，横向/纵向）；
4. 问题-方案（左右分栏 + 底部结论条）；
5. 数据 + 结论（左图表右三条结论）；
6. 团队 / 头像；
7. 客户证言（引语 + 头像 + 公司）；
8. 代码 / 终端（等宽字体 + 行号）；
9. 附录 / 备份；
10. 目录带页码。

配套：

- `Picture` 增加 `alt / caption / focus / radius / overlay`；图文比例预设 `full / 40-60 / 50-50 / grid-2 / grid-3`；scrim 令牌（黑色或品牌色，0–60%，前景文字自动选深/浅）。
- 新增 `_rules.py`（纯逻辑）：每版式的 `max_bullets / max_chars / title_lines / image_ratio`，`validate` 与编辑器共用；超限给「建议删减到 N 条 / 标题拆两行」的具体提示。
- `SlideSpec.background`（inherit / dark / light / image），配合 `palette.ramp()` 生成中性阶，解决封面/章节对比。
- 固定像素常量全部改为栅格单位或画幅比例。

### 3.6 P4：互操作与预览一致

- **导入升级**：抽取 `ppt/media` 图片并按位置映射到 image 版式；读 `a:tbl` 还原 comparison；读 chart 部件还原 chart（类型/数据/系列色）；保留备注；输出逐页「保留 / 降级为要点 / 丢弃」摘要。
- **资产目录**：落地 ADR 0055 里的 `*.assets/` + 哈希，解决跨机路径失效；导出内嵌、模板相对化。
- **模板包**：支持导出 `.potx` 与「示例模板库」（当前为 6 风格 × 8 场景，场景包在 `presets` 中列出页数与推荐风格）。
- **预览一致**：用可注入的真实字体度量接口（Qt 侧 `QFontMetrics`，纯逻辑侧 fake）替换 em 估算；建立 golden：同一模板导出后逐页解析文本盒几何，与预览几何对比，阈值 1 单位。
- **可访问性**：alt 必填、阅读顺序由占位符保证、对比度与最小字号纳入 `validate`。

### 3.8 编辑器能力（「更强的模板设计能力」的入口）

- 样式页从「密度 + 装饰强度」扩到：字号阶梯（10 项，带预览）、行距/段距、描边/圆角、语义色、图表色板、字体对（标题/正文 + 回退链）。
- 新增「设计检查」面板：对比度、最小字号、每页条目数、标题行数、图片 alt 缺失、页码版式抑制，逐项可跳转到对应页。
- 版式库按场景分组（封面 / 结构 / 内容 / 数据 / 图文 / 结束），显示每版式的容量提示（如「要点 ≤6 条」）。

## 4. 对照表：专业做法 vs 现状 vs 方案

| 维度 | 专业演示模板常见做法 | pptmake 现状 | 方案落点 |

| 主题 | 主题色/主题字体，一处改全稿变 | 颜色字体写死 | P1a |
| 页码 | `slidenum` 字段，封面不显示 | 静态文本，全页显示 | P0 + P1a |
| 正文 | 18–24pt，行距 1.2–1.5 | 15pt，行距 1.2/1.25 混用 | P0 |
| 字号体系 | 模块化阶梯 + 按画幅微调 | 固定 10 项，不随画幅 | P0 |
| 色彩 | 主色 + 强调 + 中性阶 + 对比度校验 | 6 槽，无中性阶/无校验 | P0 + P1 |

| 复用 | PowerPoint 内新建即用 | 必须回到 pptmake | P1b + P4（potx） |

## 5. 优先级、成本与风险

| 阶段 | 主要收益 | 主要成本/风险 | 依赖 |
|---|---|---|---|
| P0 排版与文案卫生 | 成品立刻「不业余」；改动集中在令牌与版式常量 | 新字号会改变现有模板观感与容量（正文变大 → 每页可放文字减少约 20%）；需要更新 golden 与 36 个设计测试 | 无 |
| P1a 主题部件 + 字段 | 换主题联动、页码正确，纯代码可控 | 需 zip/lxml 后处理与解压断言；`--flat` 双路径维护 | P0 的令牌收敛 |
| P2 原生表格/图表 | 数据可编辑、图表专业度跃升 | 预览要新增 Table/Chart 图元，工作量最大的一档 | 无（可与 P1a 并行） |
| P1b 母版/版式/占位符 | 真正成为「模板」，大纲/重设/新建版式可用 | 需二进制 base 资源与离线制作流程；占位符映射维护成本高 | P1a、P0 |
| P3 版式库与图文规则 | 覆盖面与图文表现力 | 版式多 → 预览/导出/测试三处同步成本线性增长 | P1b（占位符化后新增版式更省） |
| P4 互操作与预览一致 | 导入可用、跨机不丢资产、预览可信 | 真实字体度量、golden 框架、potx 生成 | P1b、P2 |

**建议路线（两次可验收里程碑）**

1. 里程碑 A：P0 → P1a → P2（不引入二进制资源，风险可控，用户能立刻看到质感与可编辑性提升）。
2. 里程碑 B：P1b → P3 → P4（结构性升级，需要接受一份基础模板资产入库）。

## 6. 量化验收指标

- 排版：正文 ≥18pt、最小字号 ≥12pt、行距按角色 ≥1.2、标题/正文对比度 ≥4.5:1（大字 ≥3:1）。
- 卫生：导出成品中「PPTMAKE / PPT TEMPLATE / 占位」字样为 0；封面/章节/结尾无页码。
- 结构（解压断言）：`theme1.xml` 色值 = 模板 palette；`sldLayoutIdLst` 数量 = 版式数；每页有 `title` 占位符；页码为 `a:fld`；表格页含 `a:tbl`；图表页含 chart 部件；图片含非空 `descr`。
- 一致性：13 页抽样文本盒，预览几何 vs 导出几何 diff ≤1 设计单位。
- 导入：支持范围内图片 / 表格 / 图表 / 备注保留率 100%。
- 回归：设计/核心/PPTX 测试全绿，包覆盖率不低于现状（≥95%）。

## 7. 不做 / 待拍板

**不做**：动画与转场、自由形状编辑、协作、像素级还原 PowerPoint 排版、21:9/16:10 画幅、VBA/宏。

**待拍板**：

1. 是否接受 P1b 随包分发二进制 `base.pptx`（这是「真母版」的前提）。
2. 正文默认从 15pt 提到 18pt 会让现有模板每页容量下降约 20%，是否接受（或提供「紧凑」密度作为旧口径）。
3. 是否保留 `export --flat` 一个版本的兼容。
4. 默认风格是否维持深色极光蓝（现有示例稿的观感会随母版方案变化）。

## 8. 复现与取证命令

```powershell
# 1) 生成默认 13 页模板并导出
fcmd pptmake init audit.pptmtpl.json
fcmd pptmake validate audit.pptmtpl.json
fcmd pptmake export audit.pptmtpl.json --output audit.pptx --overwrite

# 2) 解压后逐条核对本文结论
Expand-Archive audit.pptx -DestinationPath audit-pptx -Force
Get-Content audit-pptx\ppt\theme\theme1.xml            # 主题仍是 Office 默认（Calibri 等）
Select-String -Path audit-pptx\ppt\slides\slide1.xml -Pattern "PPT TEMPLATE|DESIGNED WITH PPTMAKE|01 / 13"
Select-String -Path audit-pptx\ppt\slides\*.xml -Pattern "图片占位|图表占位"
Select-String -Path audit-pptx\ppt\slides\*.xml -Pattern "<a:tbl>|<p:sldNum|<a:fld"   # 预期：0 命中
Select-String -Path audit-pptx\ppt\slides\*.xml -Pattern "srgbClr"                    # 预期：大量命中（颜色写死）
```

说明：`validate` 只做溢出与图片路径检查，不检查字号下限、对比度、页码版式抑制——这三项是本文建议新增的校验项。
