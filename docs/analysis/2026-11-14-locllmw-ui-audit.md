# locllmw 界面与设置审计（2026-11-14）

> 范围：`src/fcmd/apps/locllm/` 的 Tk 窗口 `locllmw`，覆盖概览、模型、运行、对话、代理/画图/视频/音频占位页、监测、设置。
> 性质：只读审计。**未修改任何业务代码、配置或数据**；本文档是唯一新增文件。
> 边界：不改 CLI 子命令、不改配置键与配置语义。涉及配置语义的建议在第 9 节单独标注。

---

## 0. 审计方法与口径

### 0.1 真实建窗

- 环境：Windows，桌面 2048×1152，默认窗口 `900x780`（代码默认值），最小窗口 `820x640`。
- 方法：以隔离的 `settings_path` 实例化 `LocllmWindow`，等待 6 秒（硬件检测、模型扫描、ModelScope 搜索返回），逐页 `nav.select()`，展开折叠区与三级子页后，递归读取 `winfo_class / text / state / winfo_x,y / winfo_width,height / winfo_reqwidth,reqheight` 与 Treeview 列配置。
- 页面区域实测宽度 748–785px（窗口 900px 减去侧栏与内边距），高度 755px（780px 减去标题/状态栏）。
- 截图说明：`ImageGrab` 在该桌面会话中返回空白图（桌面捕获受限），因此结论全部以**控件树 + 实际几何尺寸**为依据，不依赖截图观感。
- 探针脚本位于 `%TEMP%\locllmw_audit*`（不进入仓库）；关键数字见第 10 节。
- 基线说明：审计对象是 2026-11-14 当日**工作区快照**（该目录当时存在未提交改动）。若后续继续修改同目录，涉及尺寸/文案的条目需按新状态复测。

### 0.2 本机真实数据（用于判断“信息量是否够用”）

- 运行页模型列表：**15 个 GGUF 文件**。
- 模型 → 已安装：**7 个仓库目录，合计 230.19 GB**。
- 设置 → 引擎：2 个已安装引擎；默认引擎 `b12212`。
- 硬件：RTX 5090 D 32GB、63.4GB 内存、D 盘 1012GB。

> 同一“模型”概念在两个页面显示为 7 与 15，是本次审计的重点之一（见 R06）。

## 4. 缺失问题（现状 → 建议 → 理由 → 影响面/工作量）

| ID | 优先级 | 现状 | 建议 | 理由 | 影响面 / 工作量 |
| --- | --- | --- | --- | --- | --- |
| M01 | P0 | 引擎缺失/模型目录不存在/GPU 不可用/端口占用只在“启动失败”弹窗或某页日志里出现；概览与运行页没有全局健康状态 | 在概览与运行页顶部加一条**健康 Banner**：引擎（未安装/版本）、模型目录（不存在/空）、GPU（不可用）、默认端口（占用），右侧给“去安装/去设置/重新检测” | 用户第一眼要知道“能不能启动、缺什么”；现在要失败一次才知道 | `_locllmw_overview.py`、`_locllmw_ui.py`；数据来自现有 `engine_status`/`scan`/`hardware`。M |

## 5. 设置页三页与实际使用频率是否匹配

| 页 | 可操作控件 | 实测占用 | 使用频率判断 | 结论 |
| --- | --- | --- | --- | --- |
| 目录 | 模型目录输入、选择、恢复默认（3 个） | 556×126 / 756×698，约 90% 空白 | 一次性配置，之后极少改 | 低频页独占一个标签，浪费 |
| 引擎 | 根目录、选择、恢复默认、刷新、在线安装 3 控件、离线安装 3 控件、设为默认、检测版本、日志（约 14 个） | 请求高 772 / 可用 731；请求宽 816 / 可用 756，日志仅 57px | 安装/升级时使用，操作复杂 | 高复杂页被压扁，日志不可用 |
| 界面 | 0 个（2 个只读字段 + 1 行说明） | 298×132，约 93% 空白 | 从不操作 | 应并入“关于与诊断” |

判断：**不匹配**。设置页的划分来自三个历史窗口（目录配置、引擎管理、窗口记忆），不是用户任务；结果是低频的“目录/界面”各占一页，高频复杂的“引擎”一页塞不下，而真正高频的“模型→转换/量化”被放到二级/三级标签且日志不可见。

建议：设置收敛为 **存储** + **引擎** 两页，窗口/版本/配置路径放进“关于与诊断”折叠区（或第三个小标签，但必须有可操作内容）。

## 6. 目标信息架构

### 6.1 主结构

```text
locllmw
├─ 概览（仪表盘 + 可执行动作）
│  ├─ 健康 Banner（引擎 / 模型目录 / GPU / 端口）
│  ├─ 硬件快照（含模型目录，只读 + 去设置）
│  ├─ 智能推荐（行内“用此配置启动”）
│  └─ 运行中的服务（行内 打开 / 日志 / 停止 / 复制地址）
├─ 模型（保持 ADR 0030 的四个标签）
│  ├─ 浏览：搜索 + 详情 + 直接下载 + 打开 ModelScope
│  ├─ 已安装：仓库 7 / GGUF 15 双层计数；用于启动 / 打开 / 删除
│  ├─ 下载：当前任务 + 失败/历史 + 重试；模型目录只读 + 打开
│  └─ 转换与量化：HF→GGUF / GGUF 量化；输出目录 + 日志可见
├─ 运行（核心控制）
│  ├─ 模型与适配（含运行中标记、推荐徽标）
│  ├─ 启动参数 + 高级参数（折叠）
│  ├─ 操作栏：启动 / 停止选中 / 停止全部 / 刷新状态 | 打开 / 日志 / 复制
│  └─ 本次任务进度（页内可见，不强制跳页）
├─ 对话
│  ├─ 服务选择（含可用性原因与刷新）
│  ├─ 连接参数（折叠，改名“连接参数”）
│  └─ 空态引导 / 清空确认
├─ 监测
│  ├─ 实时：指标 + 系统负载 + GPU
│  ├─ 性能测试：场景 / 参数 / 结果（结果区最小高度）
│  └─ 日志：统一日志组件（清空 / 复制 / 打开文件）
├─ 实验室（原代理/画图/视频/音频，合并为一个入口）
└─ 设置
   ├─ 存储：模型目录 / 引擎根目录 / 服务目录（只读） / 配置文件 / 打开目录 / 迁移提示
   ├─ 引擎：默认引擎摘要 / 已安装列表 / 在线安装（确认） / 离线安装 / 日志
   └─ 关于与诊断：窗口记忆 / 版本 / GPU 驱动 / 环境体检
```

### 6.2 每页“该有什么 / 不该有什么”

| 页面 | 该有 | 不该有 |
| --- | --- | --- |
| 概览 | 健康状态、硬件快照、可执行推荐、服务行内操作 | 模型目录写入口、详细启动参数、长段技术说明 |
| 模型→浏览 | 搜索、详情、直接下载、打开市场页 | 第二份模型目录编辑、重复的“已加载”信息 |
| 模型→已安装 | 仓库/文件双层计数、用于启动、打开、删除（确认） | 与运行页重复的启动参数 |
| 模型→下载 | 任务进度、失败重试、历史、目录只读+打开 | “左侧选择模型”这类跨标签指向 |
| 模型→转换与量化 | 输入/输出、覆盖确认、输出目录打开、可见日志 | 同名二级“转换”、不可见的日志 |
| 运行 | 模型适配、参数、分组的操作栏、页内进度 | 清空日志、强制跳页、重复硬件长句 |
| 对话 | 服务可用性、连接参数、空态引导 | 与全局设置同名的“设置”入口 |
| 监测 | 实时指标、性能测试及结果、统一日志 | 与结果争抢高度的平铺布局 |
| 设置 | 低频但高影响的存储配置、引擎安装与状态 | 纯只读的空壳标签、无确认的写入 |

### 6.3 与既有 ADR 的关系

- **ADR 0027** 明确保留 10 页侧栏与 4 个占位页、运行页操作栏与日志跳转。R01/R05 属于对该 ADR 的修订，建议先更新 ADR 再落地。
- **ADR 0028** 的“概览 = 硬件/推荐/已加载”结构保留，不合并概览与运行；本次只给推荐与已加载补动作。
- **ADR 0030** 的“模型四标签、GGUF 启动列表在运行页”保留；不建议把已安装并入运行。
- **ADR 0031** 的三页设置是历史窗口合并结果；R03 需要修订该 ADR 的“界面页只读”决策。

### 待确认的决策点

> 2026-11-14 状态：决策点 1–6 已采纳并落地（P0、P1 第一批与健康 Banner）；7 单独立项。

1. **默认窗口**：是否接受首启 1080×880（老用户的窗口记忆不受影响；小屏按 85% 收缩，最小 1000×800）。

- 默认窗口几何、页面滚动、控件布局、日志最小高度、按钮分组、文案与术语。
- 确认框、空态、错误态、行内动作、复制动作。
- 这些只改 Tk 层；`SettingsPage` 已标注 `# pragma: no cover`，不涉及覆盖率口径。

### 9.3 涉及配置写入（需单独确认，但不改契约）

| 建议 | 配置影响 | 说明 |
| --- | --- | --- |
| 模型目录只在设置页编辑 | 仍写 `models_dir` | 统一为 `llmconfig.set_models_dir` 路径；概览只跳转 |
| 设置页写入前确认 | 无 | 与概览现有确认对齐 |
| 写入后刷新运行页/概览 | 无 | 修 `_on_config_changed` 的刷新范围 |
| 设置显示 `serve_dir` | 只读 | 不新增键 |
| “恢复默认”确认 | 清空对应键 | 与现有 `apply(None)` 语义一致 |
| 默认窗口尺寸调整 | `ui/locllmw.json` 的窗口记忆 | 只影响首次启动几何，不改配置语义 |

**不建议**在 UI 里做“更换模型目录时迁移文件”或“多模型目录”：前者是新的破坏性行为，后者与当前单一 `models_dir` 契约冲突，应另立 ADR。
